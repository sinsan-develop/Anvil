# FN08 실행 중인 원 자식의 소유 관측 · 결정 후보

**미채택.** 기준 main `19e0430705f667593972524ed7c1c1c4e3cf1b66`. 결정 대상은 등록된 native 감독자가 이미 생성해 보유하는 자식에 한해 관측을 발행하고, 서버가 그 관측을 협력 STOP의 현재 근거로 수락·재확인하는 소스 계약이다. 86A461의 Query 수명, 9E98의 보호 저장 배정, HUMAN STOP의 기존 정책과 승인 범위는 유지한다. 실제 SDK·자식 생성, 키 사용, DB 적용, 서비스 변경은 이번 결정에 포함되지 않는다.

## 현재 단절과 선택

`NormalStopTargets.current`는 원 grant·START·HUMAN 권한을 검산한 뒤 현재 소유 근거가 없어 412로 끝난다. 0098의 `check_stop_command`도 원 graph 검산 후 normal 쓰기를 거절한다. 0092의 `BOOTSTRAP_PREPARED`는 준비 시점의 관측이다. 9E98은 같은 등록·slot·배정에서 원장을 읽고 쓸 권위를 준다. 어느 것도 실행 중인 자식의 서버 head를 발급하지 않는다. [STOP 계약](FN08_NORMAL_STOP_TARGET_PAGE_CANDIDATE_20261115.md) · [보호 저장 계약](FN08_NORMAL_OWNED_SPOOL_PROFILE_CANDIDATE_20261116.md) · [0098](../../db/migrations/0098_normal_stop_target_page.sql.pending)

**A안**은 명시적인 HUMAN 중지 준비 1건이 있을 때만 새 관측을 요구한다. 기존 HUMAN GET은 읽기 전용이고, 기존 commands 페이지에는 사람의 준비 요청을 전달할 필드가 없다. 아무 변경 없이 두 경로를 재사용하면 아직 STOP 명령이 없는 순간의 관측을 누가 요청했는지 전달할 수 없다. 이에 HUMAN의 기존 stop-target 경로에 준비 POST 메서드 하나를 추가하고, 원 connector 명령 polling의 응답에 제어용 demand 하나를 전달한다. 별도 polling 루프·주기 관측·실행 명령·새 로그인 주체는 없다. connector의 관측 게시와 저장된 STOP 직전 확인은 아래 한 POST 경로만 쓴다. **보류**하면 normal STOP의 412와 interrupt 0을 유지한다.

## 발행과 수락

- **원 발행자.** 원 등록 세션에서 원 grant·credential slot과 첫 SEND 단발 인계를 받은 전용 native 감독자만 발행한다. 같은 감독자가 보유한 process/thread·Job, 검산된 이미지, 프로세스 생성시각과 단일 Job 구성원, 정상 재개와 현재 생존, 등록·slot 유효성을 직접 확인한다. 첫 입력·init이 확정되고 FIRST 종단이 정착된 뒤 같은 worker가 가진 원 Query에 한정한다. native가 수락한 단발 인계와 로컬 정착 근거에 결박된 요청만 목적 서명한다. 원 Query 참조 비교는 해당 isolate 안에서 수행한다. caller가 준 PID/SID·JSON·해시·SAB READY·준비 관측만으로 서명할 수 없다. 관측에는 원 핸들값·경로·환경·SDK SID·원문을 싣지 않는다.
- **원 대상.** `binding`의 정확한 키는 `projectId,connectorId,executionId,executionGeneration,grantRef,executorRegistrationRef,slotRef,parentStartCommandRef,parentStartEnvelopeHash,firstSendCommandRef,firstSendEnvelopeHash,firstAttemptRef,firstTerminalRef,sessionBindingRef,roleBindingRef,bindingGeneration,childInstanceId`다. Ref는 id/version/contentHash 전부, envelopeHash는 canonical SHA256이다. childInstanceId는 해당 supervisor가 원 자식 생성 시 한 번 발급하는 UUID다. 기존 ROOT·구식 PREPARED·다른 자식과 공유하지 않는다. 서버는 저장된 grant·START·첫 SEND·permit·등록·세션 관계를 재판독한다. 서버에 없는 로컬 FIRST 종단과 자식 생존의 출처는 등록된 목적 서명이며 서버가 OS를 직접 확인한 것으로 표시하지 않는다.
- **두 단계 인증.** 기존 normal credential·challenge·canonical target/body proof는 누가 요청했는지를 입증한다. 여기에 `PUBLISH_RUNNING_CHILD_V1`/`CHECK_RUNNING_STOP_V1`의 목적을 추가하는 것은 기존 키 사용 범위의 **확장**이다. 게시에는 별도로 같은 등록 키의 `ATTEST_RUNNING_CHILD_V1` 서명이 필요하다. 원 native 등록/slot 소유자만 동일 first-attempt에 발급한 전용 supervisor 인계에 대해 한 번의 fresh challenge, 원 요청·demand·binding·관측시각에 결합된 canonical digest를 서명한다. 실제 보유 handle 재검사가 성공한 그 supervisor의 원 private endpoint에서만 이 연산을 호출할 수 있다. 일반 POST signer, 호출자 JSON·callback, 유효 credential 단독으로는 OS 관측을 발행할 수 없다. 별도 개인키·공개키 등록·로그인 역할·원 키 반출은 없다. 목적 signer/신뢰할 수 있는 supervisor 인계 미연결이면 게시 0이다.
- **저장과 CAS.** 미적용 forward SQL에서 세대별 현재 상태 1행(고정 binding, 최초 관측 fullref/정본, 최종 신선도 서명·receipt, 준비 demand 최대 1개)을 둔다. project/execution/generation 키를 잠그고 원 부모·slot·nonce·demand·CAS를 한 거래에서 검사한다. 처음 수락한 관측 ref는 id=최초 게시 requestId, version=1, contentHash=목적 분리한 최초 게시 본문(서명 제외)의 canonical SHA256이다. 같은 child의 후행 직접 관측은 같은 원 head에 대한 신선도 확인이며, head의 id/version/hash와 이미 발급한 STOP의 기한은 그대로다. 다른 자식·세대·소유자 또는 교체한 head에는 이전 STOP 사용 불가. 이 A안은 기존 세대에 다른 자식을 재배정하지 않는다. 최초 수락 nonce와 신선도 갱신 nonce는 각각 한 번 소비한다. head 칸, 하나의 demand와 마지막 게시 receipt를 조건부 갱신하며 과거 관측을 전부 쌓지 않는다. STOP의 기존 명령·감사 이력은 보존한다.
- **유한성.** 게시·판독 canonical 본문은 각각 최대 16KiB, 세대별 현재 상태는 canonical 투영 64KiB 이하, 대기 demand는 1개다. 관측과 projection의 유효시간은 30초 이하이며 원 grant·slot·worker/child 인계 절대기한의 최단을 넘지 않는다. 서버는 신선도 갱신 시 expected head와 직전 receipt fullref를 함께 CAS하고 observedAt 후퇴를 거절한다. 최초 publish의 두 기대값은 null이다. 기존 스풀 256MiB 및 명령 이력과 별도이며 시간 경과나 게시 횟수 때문에 STOP을 영구 차단하는 256행 상한은 두지 않는다.

**명시 준비와 전달.** `POST /api/v1/projects/:projectId/executions/:executionId/stop-target`의 exact body는 `{requestId,generation,grantRef}`이다. 현재 원 HUMAN 세션/CSRF·회원/제어·원 5튜플·STOP 정책을 GET과 동일하게 검산한다. 새 효과는 승인된 원 주체가 해당 실행의 신선한 관측을 한 번 요구하는 것뿐이다. 현재 head가 아직 유효하면 기존 projection을 200 반환하고 새 게시·demand 0이다. 신선한 근거가 없으면 새 시스템 UUID의 demand를 최대 30초/원 기한까지 한 칸에 저장하고 `202 {demandRef,expiresAt}`를 반환한다. 같은 주체·grant의 동시 준비는 기존 유효 demand로 합치고 기한 연장 0, 다른 주체/세대는 거절한다. 원 connector의 인증된 commands GET 응답만 `X-Anvil-Running-Child-Demand` 헤더(선택, 단일값, base64url canonical `{demandRef,expiresAt}`, 최대 1KiB)를 받는다. 페이지 item·서명된 envelope·cursor·ACK 의미는 불변이다. 활성 owner가 다음 기존 poll에서 유효 demand를 받으면 **원 FIRST 종단·현재 자식·원 인계가 모두 있을 때만** 게시한다. 같은 demand 재수신으로 자동 중복 게시하지 않는다. 202 뒤에는 기존 HUMAN GET으로 준비 결과만 확인하며 GET은 demand를 만들지 않는다. polling이 중지됐거나 demand·원 grant가 먼저 만료되면 정상 200이나 interrupt를 보장할 수 없다. 동시 새 관측이나 주기 refresh 없이, 성공한 준비의 원 기한 안에서 정상 저장·수신 기회를 보존한다.

## STOP과 불명 처리

**게시.** `POST /api/v1/connectors/:connectorId/executions/:executionId/running-child-ownership`에 `{purpose:'PUBLISH_RUNNING_CHILD_V1',requestId,demandRef,binding,previousHeadRef,previousReceiptRef,observedAt,expiresAt}`의 고정 body를 보낸다. 목적 확인서와 transport proof는 인증 외피에 둔다. 최초 수락/신선도 갱신 응답은 `{observationRef,receiptRef,observedAt,expiresAt,executionAuthorized:false,dispatchPerformed:false}`이며 receiptRef는 해당 게시 body 전체의 목적 분리 fullref다. 같은 거래에서 demand를 소비한다. HUMAN 준비 GET·STOP 제출은 원 head와 마지막 직접 관측의 신선도를 검산해 기존 projection/stopScopeRef를 만든다. 제출은 0098의 무조건 거절을 새 검산으로 교체하며 기존 graph·감사·outbox·역완결은 그대로다.

**중지 직전.** 같은 connector POST의 두 번째 exact body는 `{purpose:'CHECK_RUNNING_STOP_V1',requestId,commandRef,envelopeHash,stopScopeRef,observationRef}`다. 요청마다 새 전용 nonce/transport proof를 검산한다. 잠금 안에서 저장 STOP·원 target·원 START·실행 세대와 head fullref, 원 등록·슬롯·grant 유효/미회수, 원 HUMAN 5튜플과 현재 회원·제어를 확인한다. 원 permissionPolicyRef·PROJECT budgetPolicyRef·sourceScopes와 현재 head가 일치해야 하며 requestExecutionStop의 현재 DENY/REQUIRE_APPROVAL·정책 교체·한도/기한 초과 시 거절한다. 원 STOP·마지막 관측 만료·실행 인계·현재 credential 기한의 최단까지만 기존 NormalStopProjectionV1을 반환한다. 이 경로는 nonce 소비 외 head 쓰기 0이다. 로컬은 기존 `readCurrent`가 요구하는 각 시점에 판독하고 원 핸들을 다시 확인하며, 같은 worker·Query 객체와 정확한 command/envelope·scope에 결합한다. 원 STOP 시도 정착 뒤 원 Query interrupt 최대 1회다. 판독 직후 회수·종료의 분산 경합은 남으며 강제 kill·즉시 회수의 원자성은 보장하지 않는다.

**불명·종료.** 응답 유실 후 자동 재송신 0. 명시 확인은 PUBLISH와 **동일한 body bytes·원 관측 목적 확인서**에 새 transport challenge/nonce와 새 transport 서명만 붙인다. 새 외피는 이전 게시 body/확인서 digest에 결합한다. 마지막 수락 receipt의 requestId·body·원 확인서가 모두 같으면 현재 권한 재검산 뒤 저장된 원 결과만 반환하며 만료시각·head·demand 변경 0이다. 수락 기록이 없거나 이미 대체된 확인 요청은 원 demand/원 관측 challenge가 유효하지 않으면 UNKNOWN으로 보존한다. 옛 소비 nonce를 재사용하거나 새 nonce를 새 관측 확인서로 해석하지 않는다. 다른 body/서명·낡은 CAS·다른 자식은 거절한다. 원 child 종료·감독 상실·등록/slot 소실·grant 회수 시 원 native 신규 발행/interrupt는 0이다. 서버가 모르는 물리 종료는 마지막 관측 만료까지 보일 수 있어 로컬 재검사가 필요하다. 한쪽 증거 소실·UNKNOWN/물리 종료는 논리 완료·writer 해제·STOP 성공이 아니며 새 child/Query/시도 자동 생성 0이다.
