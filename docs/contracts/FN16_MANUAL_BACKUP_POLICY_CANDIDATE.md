## 3. B안의 구체 계약 제안

### 3.1 보호 참조

- 서버가 허용한 저장 호스트/설치 root 목록에서 대상을 선택한다. 브라우저의 pathHint를 서버 파일 접근 경로로 바로 실행하지 않는다. 대상 표시 이름·server-owned ID/VersionRef·소유 project/사용자·등록/검증 시각·사용 가능성·허가 범위·무효화 이력을 저장한다. raw 경로는 일반 목록/로그/Agent 맥락에 넣지 않는다.
- 키는 Agent 계정과 분리한 Anvil 백업 전용 참조다. UI에는 표시 이름/정확 버전/비밀 없는 상태만 반환한다. 원 키를 DB/manifest/로그/승인 위험 설명/Agent에 넣지 않는다. 키 교체는 새 버전이며 기존 백업이 요구하는 옛 키의 필요성을 표시한다. 자동 폐기0이다.
- 키 준비/보호 저장은 실제 서버 플랫폼에서 지원·검증한 방식만 사용한다. Windows DPAPI를 WSL 서버 키 보호라고 주장하지 않는다. 지원 어댑터·권한·보호 근거가 없으면 KEY_PROTECTION_UNVERIFIED로 저장/생성을 거절하며 평문 fallback0이다. 구체 보호 adapter 채택과 실제 키 준비는 필요한 결정이다.
- 보존 참조의 첫 버전은 자동 삭제 OFF·현재/과거 참조와 실패본 보존이다. 기간을 임의로 만들지 않는다. 검사 참조는 실제 지원하는 manifest/hash/본문·원문/관계·schema/키 가용성 검사를 선택하며, 용량/파일수/시간의 유한 실행 한도를 함께 고정한다. 미정 한도를 무제한으로 바꾸지 않는다.
- 공개 연산 후보는 보호 참조의 등록/개정·고정 버전 조회/선택 목록이다. 임의 경로 탐색·키 조회/다운로드 API는 만들지 않는다. 실제 wire/권한/DTO와 허용 파일 목록을 상세화한 뒤 구현한다. 이 추가 등록 계약은 기존 exportProject 승인에 상속하지 않는다.

### 3.2 정책·수동 명령·이력

P02의 BackupPolicyVersion 필드 이름은 유지한다. schedule은 최초 MANUAL만 허용하고 include 각 항목과 sourceSelection을 사용자에게 명시한다. maxBytes는 유한 정수이며 승인된 최초10GiB 범위와 실제 저장소/검사 한도의 더 좁은 값을 적용한다. 초과·미확인 대상/키·무효화되었거나 현재 선택 계약과 불일치하는 ref·다른 프로젝트 ref는 생성 전 거절한다. 유효한 고정 과거 버전이나 기존 백업 복호화용 옛 키를 일괄 거절하지 않으며, 새 백업 선택 가능성과 과거 복호화 가용성을 구별한다.

saveBackupPolicy는 불변 버전/이유·현재 로그인/소유자/client/control·별도 명시 정책·정확 이전 버전·receipt/audit를 저장한다. 정책 저장으로 백업을 시작하지 않는다. createBackup은 정책 전체 ref·자료 포함 선택/이유·현재 권한·기한·원명령 ID를 고정하고 job 접수와 완료를 구분한다. 같은 원명령은 같은 job/영수증을 재조회하며 파일 작성/소비를 반복하지 않는다.

job은 접수→수집→검사→완료 또는 실패/결과미확인으로 이력을 남긴다. 단계 변경은 원명령/정확 정책·수집 기준·fence/현재 job 버전과 연결하고 별도 새 사용자 권한을 발급하지 않는다. 현재 제어·정책/기한·키/대상 근거가 바뀌면 새 파일 publish를 차단하고 기존 시도/사본을 보존한다. 재시작 후 미완료 job을 자동 재실행하지 않고 원 결과/파일 지문을 재대조해 사용자가 명시적으로 조정한다.

### 3.3 실제 자료 수집과 공개 파일

- 같은 DB 기준에서 제공된 방법론/헌법·문서/원문·대화/지식·계획/설계 추적·판단/승인 이력·결과/증거·작업현황/관계·실행/감사 이력·연결 설정의 비밀 제외 참조와 제공된 알림 설정/이력을 수집한다. 포함 항목별 실제 collector/표·버전·관계 목록을 구현 카드에 고정한다. 제공되지 않은 필수 collector를 빈 배열로 완료 처리하지 않는다.
- 포함/제외 preview와 manifest에 정확 이유·누락·읽기 실패·실제 bytes/hash/버전/관계를 남긴다. 사용자/Agent 로그인 Secret·인증 token·현재 세션·활성 writer/제어/승인 권한은 이전하지 않는다. 관련 사건/판단은 현재 권위가 아닌 이력으로만 보존한다.
- sourceSelection은 기존 검증된 소스 등록/허가/관측 ref가 있을 때만 해당 tracked/미추적/필요 ignored·삭제를 명시 선택한다. 지원되지 않는 소스가 포함되면 생성 전에 거절한다. source 제외 선택을 source 포함 백업 PASS로 표시하지 않는다.
- PostgreSQL의 하나의 Repeatable Read 기준과 실제 불변 artifact 버전/hash를 결합하는 수집안을 권장한다. 이것만으로 파일과 DB의 원자성을 보장하지 않는다. 파일은 같은 ref의 바이트/hash를 읽고 격리/상태 변화와 최종 기준을 publish 전에 재검사한다. 자료 수집 snapshot과 별도의 현재 DB 경계에서 publish 직전 인증/제어/정책·키/대상·격리를 재검증하고, job 상태 전환·정확 승인 소비/재사용 금지를 같은 DB 경계에 결박한다. 파일 publish와 DB commit은 원자적이라고 주장하지 않으며 중간 실패/불명 상태는 보존·재대조한다. 전체 DB transaction/lock·페이지 수집·기한과 파일 공개/commit 사이의 정확 실패 창을 구현 카드에서 검수한 뒤 채택한다. [PostgreSQL15 격리 문서](https://www.postgresql.org/docs/15/transaction-iso.html).
- 기존 createFileManifest/createFileBundle/validateFileRestore의 실제 검사를 재사용하고 현재 문서1개 반출 계약은 유지한다. 출력은 새 job 전용 staging→암호화/검사→최종 publish다. 실패/COMMIT 불명 때 성공 manifest를 만들거나 참조된 사본을 자동 삭제하지 않는다.
- 암호화 후보는 인증된 AES-256-GCM이며 키와 job별 nonce·tag/AAD/자료 형식 버전을 고정하고 완전 인증 확인 전에 복원 데이터를 채택하지 않는다. 정확 형식·nonce 수명/중복·키 보호/유실 시험을 검수해야 하며 아직 채택/구현0이다. API 근거는 [Node24 crypto](https://nodejs.org/docs/latest-v24.x/api/crypto.html#class-cipheriv)이며 문서 열람이 구현/보안 합격을 의미하지 않는다.

## 4. 상세 화면·위임/검수 단위

UI14에 기존 ‘선택 원문 반출’을 유지하고 ‘전체 자료 수동 백업’을 분리한다. 보호 참조 설정→불변 정책 작성/저장/조회→포함·제외/용량/미확인 preview→수동 생성→job 진행/실패/원명령 재확인→manifest/검사 결과 조회 순서다. 사용자는 원본 자료를 덮거나 Agent를 실행하지 않는다. 키/대상 미설정·인증/권한·용량·누락/변조·부분 실패·결과미확인을 구별한다.

업무는 (1) 보호 참조 등록/조회·화면, (2) 정책 불변 저장/조회·미적용 SQL, (3) 실제 제공 자료 collector/같은 기준 manifest, (4) 수동 job/암호화 파일·재조회·실패 조정, (5) UI14 전체 여정/별도 검증 복원으로 구분하되 저장/화면 중 일부만 완성했다고 하지 않는다. 동시에 같은 파일을 수정하지 않고 앞의 실제 ref를 다음 업무가 소비한다. 구체 WorkInstruction은 상세 채택 뒤 발행한다.

최소 검수는 정상 정책→수동 생성→원문/관계 조회, 다른 프로젝트·무효화/불일치 ref·변조·권한/기한·키 미확인 거절, 누락 blob/격리/용량·부분 파일/DB 실패·응답 유실/재시작 조정·실행 권한 자동 복원0이다. fixture/build는 실제 DB/파일/복원/사용자 인수와 구분한다. 합성 일회 자원은 생성 전 이름/owner/수명/정리를 별도 등록한다.

## 5. 지금 필요한 정확 결정

PMO 위임 범위에서 A/B 중 최초 구현 경로와 B의 보호 참조 등록/키 보관 상세화를 채택할지 판단한다. B 선택만으로 아직 미정인 키 보호 adapter·보호/유실·이식 절차까지 구현 승인된 것으로 취급하지 않는다. 그 세부 계약을 먼저 확정하고 코드·화면·미적용 SQL·합성 검증의 정확 허용 범위를 고정한 뒤 실제 DB/키/경로·서비스 적용과 분리한다. 실제 설정값/키/대상·새 보호 adapter 실행·정식 DB/권한·서비스·외부 배포/비용은 이 후보의 채택만으로 실행하지 않는다. 불가한 항목만 분리하고 이미 승인된 나머지 작업을 중지하지 않는다.
