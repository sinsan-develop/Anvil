# FN12 등록 시험 명령 직접 관측 계약 후보

## 판단과 승인 범위

**상태는 후보이며 제품 연결 전이다.** 신산님의 2026-11-27 직접 채택은 같은 등록 실행·세대에서 실행기가 직접 관측한 명령, 종료 코드, 환경, 커밋, 산출물 해시를 보호 보관하여 검수 근거로 사용하는 범위다. [보호 실행 증거 v1](FN12_NORMAL_EXECUTION_EVIDENCE.md)과 [FN12 업무 카드](../work_packages/FUNCTION_WORK.md), [v3 설계 §7.3](../design/Anvil_설계서_v3_초안.md)에 근거한다. 당시 채택 범위에서 정확 참조·원 관측·증거 정착의 순서를 소스와 합성 모델로 구체화할 수 있다. 등록 시험 명령을 실제로 발급하고 실행시키는 계약은 아래 변경점을 따로 확정해야 한다.

| 선택 | 범위 |
| --- | --- |
| A. 소스·합성 모델 | 정확 시험·프로필 선택, 현재성 입력의 증명 요구, 단회 접수 상태, 원 핸들에서 제공받는 종료·측정의 정규화, 보관/재확인 계약을 모델로 검산한다. 실제 원 관측 포트가 미구성인 조립에서 증거 발급과 실행 효과는 0이다. 이 후보 작성과 원형 모델은 현재 채택 범위다. |
| B. 향후 목적 실행 | 사용자가 명시 선택한 고정 시험 프로필만, 같은 등록 실행기·현재 WORK에서 단회 실행하도록 전용 명령 권위와 원 관측 포트를 채택한다. 필요한 경계는 고정 프로필의 보호 발행·폐기, 명시 실행 권위와 접수 원장, 현재 수송·credential에서 허용하는 목적, 실제 원 핸들·측정 및 검수로의 전달이다. 정확 수송·효과·최단 허용 기한·저장 검증을 확정하기 전에는 호출선을 활성화하지 않는다. |

이번 작성 범위는 A다. B에 필요한 최소 변화는 **등록 프로필에 묶인 명시 시험 실행 권위**와 **같은 등록 실행기가 그 권위를 한 번만 소비하는 목적별 전달**이다. 기존 제출·검수와 START·SEND·STOP의 권한 및 승인 절차는 이어서 적용한다. 범용 셸 전송, 새 서비스·키·역할, SDK 출력 신뢰 확대는 포함하지 않는다. 실제 프로세스 실행·키 사용·운영 DB·권한·서비스·SSH는 이번 후보 작성 범위 밖이다.

## 확정 업무·시험과 등록 프로필 선택

1. 사용자는 현재 프로젝트에서 원 확정 계획·업무·AF05 TC와 하나의 고정 등록 시험 프로필을 명시 선택한다. 서버는 권한 있는 고정 원문에서 확정 계획 ref, 업무 코드, AF05 원문 버전, TC ID와 해당 시험의 canonical 해시를 확인한다. AF05 원문과 확정 계획 카드의 귀속 관계가 확인된 시험만 수락한다. TC ID·화면 문구·최신 후보를 추정하여 선택하지 않는다. 기준이 바뀐 경우 새 버전을 다시 확인한다.
2. 제안하는 프로필은 등록 실행기·배포본·고정 환경에 귀속된 불변 `profileRef`다. 프로필 원문에는 정확 실행 이미지 참조 및 해시, 토큰 배열의 해시와 보호 원문 참조, 고정 작업 루트/입출력 범위, 고정 환경 버전과 지정 commit, 종료 및 자원 한도가 들어간다. 산출물은 사전 지정한 이름·보호 출력 범위로 한정한다. 플랫폼 실행기는 고정 실행 이미지와 인자 배열만 사용할 수 있다. 사용자가 넣은 셸 문자열, argv 덧붙이기·치환, 경로 탐색, 기본 작업 디렉터리 전환, 명령명 fallback은 제외한다. 등록키·환경 변수 전체·Secret은 명령·감사·UI에 담지 않는다.
3. 현재 동일한 등록·환경·프로필 버전의 효력을 확인한다. 기존 설치/배포의 고정 근거, 보호된 프로필 원문, 현재 취소·폐기 상태를 대조할 실제 발행/판독 주체가 필요하다. 실행자가 반환한 프로그램명, 전달 해시, 시험 성공 메시지로 프로필의 등록 상태를 올리지 않는다. 프로필 등록이나 변경의 사용자 효과와 보호 위치는 B에서 정해야 하며, 이 문서에서 새 등록 API·테이블·역할을 확정하지 않는다.
4. 고정 이미지와 argv는 최초 호출을 식별한다. 하위 프로세스, `npm` 생명주기 스크립트, 설정/의존성에 따른 동작, 네트워크·외부 쓰기는 별도 격리 검산 대상이다. 목적 원 소유자는 격리 경계에 속한 하위 프로세스에도 같은 정확 소스 읽기 범위, 호출 전용 출력, 기존 실행 시간·자원·비용 예산과 외부 접근 제한이 적용됨을 확인한다. 어떤 실행 경로에서 이를 보장할 수 없으면 해당 프로필은 미구성으로 두고 시작 효과를 0으로 유지한다.

## 단회 접수와 원 관측 동선

1. **현재 실행 확인.** 접수 시 현재 로그인·사용자/client·단독 제어·목적 정책을 확인한다. 고정 임무와 같은 WORK의 실행 ID·세대, 기존 등록·허가·credential 세대·원 시도를 하나의 인증 경계에서 대조한다. 같은 실행의 고정 환경/소스 관측 버전과 정확 Writer head, authority epoch, lease, source fence를 다시 확인한다. 값이 오래됐거나 원 source/writer가 회수·불명·충돌 상태면 신규 접수는 보류한다. CONTEXT_REVIEW와 과거 제어권의 자료에 실행 권위를 이월하지 않는다. 프로젝트 소스의 추가 쓰기와 새 writer 배정은 이 실행 접수로 발생하지 않는다. 보호된 시험 출력은 기존 상한·예산·승인 범위 안에서만 허용한다.
2. **현재 요청에 한정된 목적 권위.** 후보에서는 사람이 확인한 정확 보호 요청을 단위로 삼는다. 서버의 불변 요청에 프로젝트·임무·확정 계획·AF05 TC·프로필·환경·commit, 등록·허가·실행 세대·로컬 시도, 원 dispatch, 보호 source/writer 근거와 정책·예산·별도 승인 근거를 결박한다. B의 새 명령은 보호 `requestId`와 canonical 요청 해시, 목적 한정 단회 증거, 정확 기한을 가진다. 유효 구간은 기존 사용자 허가·등록/credential·WORK·source/writer·예산 및 프로필 한도의 최단 기한이다. 이전 요청의 기한을 연장하거나 관측 결과를 다시 써서 권위를 살리지 않는다. 별도 실행 허가나 정책 승인이 필요한 경우 기존 절차의 exact 명령 대조를 그대로 거친다.
3. **단회 소진.** 등록 원 소유자의 보호 접수 장부가 `(projectId, executorRegistrationRef, executionId, executionGeneration, requestId)`의 정확 요청 해시를 원자 비교하고 소진한다. 최초 정상 소진에서만 개별 호출의 `occurrenceId`를 할당하고 원 시도·접수 근거를 묶는다. 같은 요청의 중복·동시 수신에는 기존 상태 또는 완료본만 반환한다. 같은 ID의 다른 payload, 다른 등록·세대·시도, 만료·회수 후 새 소진은 거절한다. 소진 정착을 읽어 확인할 수 없으면 프로세스 시작 효과 0과 불명 보존을 적용한다. 명시적으로 다시 시험을 수행할 때에는 기존 요청을 보존하고 모든 현재 조건을 대조하여 새 독립 요청을 발급해야 한다.
4. **원 핸들 시작.** 목적 전용 native 원 소유자가 자신이 인수한 고정 이미지와 프로필·원 요청·현재성을 재검산한 직후 개별 시험 명령의 원 핸들을 취득한다. 권한 경합 시 반환값으로 이전 값을 되살리지 않는다. 시작 사실은 같은 원 핸들과 생성 증거가 확인된 경우만 기록한다. SDK child·SDK 이벤트·stdout에서 원 명령이 발생했다고 추론하지 않는다. 타 PID 재열기, 제3자 프로세스의 인계, 임의 provider callback으로 원 소유를 복원하지 않는다. 해당 원 포트가 구성되지 않았다면 실행·측정·증거 발급은 0이다.
   - B는 원 owner가 취소·회수·lease 폐기와 물리 시작을 같은 보호 경계에서 직렬화하는 최소 시작 지점을 정해야 한다. 시작 전에 회수 또는 취소가 선점하면 물리 시작 0이다. 시작이 먼저 정착한 경우에는 그 원 핸들만 기존 한도에서 회수한다. 원자적 소진이나 서버의 사전 조회만으로 원격 회수와 로컬 시작 사이의 경합이 닫혔다고 판정하지 않는다. 원 epoch·lease를 실제 시작까지 결박할 수 없거나 한번의 시작 결과가 불명이면 추가 시작·재시도 0과 `UNKNOWN` 보존을 적용한다.
5. **종료와 직접 측정.** 취소·만료·회수와 원 핸들의 자발 종료 관측을 동일 소유자 경계에서 직렬화한다. 종료 전 강제 정리 요청이나 효과, 소유 손상, 확인 불명이 있으면 자발 종료 근거를 발급하지 않는다. 원 핸들의 종료가 먼저 확인되면 0이 아닌 종료 코드도 정확히 보관한다. 신호·강제 정리·미관측을 합성 종료 코드로 표준화하지 않는다. 동일 호출의 보호 원본에서 argv digest와 UTC 시작·종료·관측 시각, 환경 설정 ref/실측 fingerprint, Git 객체 형식과 전체 commit, 보호 산출물의 논리 이름·길이·SHA-256·`artifactRef`를 수집한다. 고정 소스와 worktree 경계는 commit과 별도로 확인한다. 환경·Git·원 바이트가 불일치하거나 보호 저장이 불명인 경우 정착 증거는 발급하지 않는다.
   - 산출물은 해당 `occurrenceId`에 전용으로 귀속한 보호 출력에서만 판독한다. 원 소유자는 시작 전 대상과 이름의 부재, 해당 호출의 생성 근거, 열린 파일의 신원, 측정 후 같은 파일 신원·길이·해시와 보호 참조를 확인한다. 사전 존재 파일, 이전 호출의 같은 이름·같은 해시 파일, 경로 교체·링크·외부 파일 가져오기는 해당 호출의 출력으로 받아들이지 않는다. 우연히 내용이 같은 새 출력도 이번 호출에서 새로 생성한 원 신원이 확인되어야 한다.
6. **보관과 검수 전달.** 명시 시험 권위의 정확 전송 명령을 `dispatchCommandRef/dispatchEnvelopeHash`로, 개별 물리 호출의 보호 원자료를 `captureRef`로 정착한다. 원 WORK/START와 필요시 상위 SEND는 접수 이력에서 별개 참조로 보존한다. 기존 [증거 v1 원형](FN12_NORMAL_EXECUTION_EVIDENCE.md)을 사용하고, 동일 등록의 보호 근거로 원 command·소진·capture·환경·산출물과 증거 hash를 검산한다. 서버 정착은 정확 원 영수증·감사·정산과 같은 거래에서 이뤄져야 한다. 검수 화면은 같은 임무·시험·결과·기준/환경/commit의 고정 근거만 읽어 비교하며 출처 또는 시험 종류를 올려 해석하지 않는다. 기존 `WORKER_CLAIM`, `PROVIDER_CLAIM_ONLY`, 일반 ACK, 검수·완료 결정의 의미는 그대로 유지한다.

| 미구성·승인 또는 정확 원문 대기 | `보류`. 명령 공급·소진·실행 효과 0, 변경된 TC·프로필은 새 명시 선택을 요구한다. |
| 시작 전 확정 거절 또는 취소 | 원 소진과 시작 효과 유무를 확인해 기록한다. 이미 소진한 요청에는 신규 효과 0. 실패 코드나 검수 합격으로 대체하지 않는다. |
| 원 소진 및 실행 중 | 같은 요청은 보관된 정확 소유·진행 상태만 읽는다. 정지·회수와의 경합에서 현재 원 소유의 한정 cleanup만 가능하고 새 명령이나 실행 권위는 발급하지 않는다. |
| 자연 종료의 원 핸들·측정·정착 확인 | 정확 종료 결과와 원 영수증의 고정 참조를 반환한다. 0이 아닌 종료 코드도 사실 기록으로 보존한다. 검수 적합 판정에는 기존 기준과 적격 산출물 검증이 별도로 필요하다. |
| 취소·강제 회수·timeout·부분 측정·close/readback/COMMIT/응답 불명 | `UNKNOWN` 또는 확인된 취소로 구분하여 원 요청·원 소진·원 소유 기록을 보존한다. 새 nonce·재전송·재실행·자동 삭제는 금지한다. 보호 조회에서 동일 요청·해시·원 정착을 확인한 경우에만 기존 결과를 반환한다. 누락 증거는 계속 미확인이다. |

롤백은 목적 전용 신규 권위 발급 및 접수를 비활성화한다. 기존 START/SEND/STOP과 역사 판독을 유지하고, 이미 시작됐거나 결과가 불명인 대상은 원 소유자만 승인된 정리·재확인 절차에서 처리한다. 이미 처리된 효과를 로그 삭제나 임의 회수로 철회하지 않는다. 역사 영수증과 보호 원자료는 이전 버전 reader에서도 보존 가능해야 한다. 현재 사용자가 읽을 수 있는 범위와 과거에 확인된 원 권위의 범위를 각각 대조한다.

## 후속 파일 경계와 필수 회귀

| 단위 | 기존 경로와 변경 범위 후보 |

| 선택·접수 | `apps/server/modules/traceability/work-plans.ts` 및 `work-plan-card.ts`의 고정 원문·업무/TC를 재사용한다. 서버의 목적 승인과 동일 거래 접수는 현재 실행·Writer 검산 뒤 별도 구현한다. 신규 command DTO·소진 저장·정확 소비 목적의 필요 최소만 B에 포함한다. |
| 배타 원 소유 | `apps/connector/runtime/normal-first-send-owner.ts`의 등록·원 dispatch·시도 결박을 참조한다. `normal-owned-spool-profile.ts`와 native의 별도 목적 명령 핸들에서 관측 포트와 배타·close 검산을 구현할 수 있는지 대조한다. SDK supervisor 및 준비 프로세스의 출력을 개별 시험 명령의 관측 원본으로 연결할 수 없다. 파일·실행기 조립의 적용 범위는 채택 후 작업 단위에서 고정한다. |
| 보호 정착 및 FN12 | `contracts/runtime/normal-result-execution-evidence-v1.ts`의 바이트 검산을 사용한다. `normal-observations.ts`의 일반 주장 원장은 그대로 유지한다. 목적별 보호 보관·재조회 결과만 `apps/server/modules/results/result-evidence.ts` 및 `project-result-reviews.ts`와 시험 입력에 연결한다. |

| 시험 | 통과 조건 |
| --- | --- |
| 확정 원문·고정 프로필 | 같은 업무 코드나 TC ID를 가진 다른 계획/AF05, 다른 profile/environment/commit, 서명·hash 교체, 변경된 argv/작업 루트, 범위 밖 산출물을 검산 전에 실행하지 않는다. 정상은 최초 정착한 정확 원문으로 재확인한다. |
| 현재 권위·경합 | 다른 등록/credential/실행/세대/시도, 만료·제어 변경, 잘못된 source·Writer head/epoch, 닫힌 예산·별도 승인 부재에서 시작 0. 회수·취소와 실제 시작의 동시 선점, 시작 결과 불명, 소진 직전/직후 실패에서 새 소진·중복 시작·재시도 0. 하위 프로세스·npm 생명주기·외부 접근의 격리 증거가 빠진 조립에서 시작 0. |
| 원 핸들·종료 | 자발 종료 코드 0과 0이 아닌 값을 구분한다. 취소/강제 종료와 자연 종료 경합, 물리 핸들 교체, SDK 호스트 exit·공급자 주장, 미측정 또는 저장 불명은 정식 관측으로 수락하지 않는다. 같은 상위 dispatch의 독립 명령은 서로 다른 `captureRef`와 증거 ID를 가진다. |
| 저장·재조회·롤백 | 보호 원자료·산출물 바이트/hash 변조, 관측 시각 역전, append/flush/close/COMMIT·응답 유실에서 새 명령·nonce·증거 재발행 0. 사전 존재·이전 호출의 동일 이름/동일 hash·측정 중 신원 교체는 출력 근거 0. 원 요청/정상 정착 조회, 기다리던 후보의 다른 binding 교체 거절, 접수 비활성화 후 과거 증거 판독, 기존 일반 START/SEND/STOP/ACK 호환을 검증한다. |
| 검수 보호 | 같은 exact TC/환경/Git/산출물의 적격 근거만 표시한다. 결손·미실행·권한 회수와 대조 상태를 구분하고 검수·합격·실패 집계·재개를 자동으로 바꾸지 않는다. |

A의 합성 모델은 상태·폭·exact 바이트와 부작용 호출 0을 증명하는 범위다. 실제 원 명령 핸들의 생성·관측·정리, 설치된 호스트와 키·권한·저장 환경, 물리 실행 경합·서버 COMMIT 및 운영 인수 결과는 별도의 정확한 실행안과 실제 증거가 필요하다.
