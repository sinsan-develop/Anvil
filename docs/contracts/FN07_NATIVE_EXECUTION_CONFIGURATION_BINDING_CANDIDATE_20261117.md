# FN07 등록 native의 실행 구성 결박 · A안 결정 후보

**미채택 · 소스 전용.** 기준 main `19e0430705f667593972524ed7c1c1c4e3cf1b66`. 결정할 내용은 기존 등록의 로컬 설정 담당자가 선택한 실제 Windows 디렉터리와 허용한 실행 구성을 native가 보존하고, 원 normal grant의 정확한 환경·시도에만 이를 사용할 수 있게 하는 권위다. SDK Query 호출·첫 SEND·협력 STOP 자체의 재승인 대상은 아니다. 실제 폴더 선택·권한 적용·배포·키 사용·Secret 접근·모델 실행은 이번 결정 범위 밖이다.

## 이미 있는 근거와 빈 부분

1. environment 버전은 host·sourceRoots·commandProfileRefs·secretRefs·policyRef를 고정한다. 명령 메타데이터는 program·argsTemplate·workingDirectory(sourceRootRef, relativeDirectory)·secretSlots를 선언하고, 환경 저장 시 등록/경로 선언 또는 snapshot 계보를 검산한다. 이 메타데이터의 표시명·pathHint·과거 snapshot은 지금 열 OS 디렉터리의 신원이나 실행 허가가 아니다. [환경 형상](../../contracts/runtime/environment-configuration-v1.ts) · [환경 저장](../../apps/server/modules/connections/project-environments.ts) · [원 경로 선언](../../apps/server/modules/connections/source-root-input.ts)
2. 원 START/첫 SEND envelope에는 environmentRef·sourceScopes가 있다. native credential slot의 scope는 projectId·connectorId·executionId·executionGeneration·grantRef·credentialGeneration 여섯 필드다. slot만으로 물리 root·cwd·명령/환경을 정하지 않는다. 9E98 root는 스풀 보관용이다. 86A461 §70과 기존 process-tool 후보도 실제 실행 구성의 공급자가 미확인임을 구분한다. [slot 검산](../../apps/connector/native/NormalExecutionCredentialSource.cs) · [86A461](FN07_NORMAL_QUERY_OUTPUT_OWNERSHIP_CANDIDATE_20261116.md) · [process-tool §3](FN07_CLAUDE_DRIVER_PROCESS_TOOL_BOUNDARY_CANDIDATE_20261106.md)
3. **배포 입력 부재**와 **로컬 선택 권위 부재**는 별개다. 고정 SDK·runtime·CLI closure를 인증할 설치 산출물이 없으면 package unavailable이다. 그 산출물이 있어도 이 후보의 로컬 설정이 없으면 configuration unavailable이다. `770175 IMAGE_SIZE`에서 이미지·실행 형상·경로를 도출하지 않는다.

## A. 최초 설정·보호 저장

- 등록을 소유한 기존 데스크톱의 보호된 설정 창에서만 사용자가 **현재 등록에 묶을 로컬 폴더를 직접 선택하고 확인**한다. 새 로그인 역할은 없다. 설정 주체는 원 등록·현재 peer·설정창 sender/frame·owner epoch에 묶는다. 브라우저 페이지/renderer가 절대경로·환경변수·argv·임의 native 명령을 입력하는 인터페이스는 없다. settings.html의 `connect-src none`을 유지한다. 설정창은 선택 식별자만 shell main에 넘긴다. shell.cjs의 `createShell`이 기존 `createRegistrationClient`와 같은 `persist:anvil-web` 세션·고정 origin·원격 view·generation·authEpoch·lease.check를 캡처한다. 신규 내부 `execution-configuration-read-client.cjs`는 그 세션의 fetch로만 기존 HUMAN GET `/api/v1/projects/{pid}/{collection}/{id}/versions/{version}`을 호출한다. collection은 `environments`, `command-profile-metadata` 두 상수로 제한한다. 첫 fullref는 원 서버 read 응답의 프로젝트·목적·버전·canonical hash로 검산하고 두 번째 fullref는 첫 snapshot의 commandProfileRefs에서 가져온다. 기존 `apps/web/src/features/connections/environment-configuration-api.ts`의 `readEnvironmentConfiguration`/`validateEnvironmentView`와 같은 형상·자료량·hash 규칙 및 서버 `apps/server/modules/projects/routes.ts`의 원 HUMAN 읽기 정책을 적용한다. 리디렉션 거절, 매 await 전후 원 창·origin·authEpoch·등록 동일성 검사, 응답 ref·snapshot 불일치, 회수된 프로필 또는 현재 구성 상태 CHANGED/UNAVAILABLE 시 발급 0. renderer JSON은 snapshot 공급 경로가 없다. 실행 직전에는 현재 normal grant/slot/permit과 원 envelope의 exact environmentRef를 별도로 재검산하며 현재성 근거 소실 시 실행 0. 새 웹 API·DB행·일반 파일탐색 API는 추가하지 않는다.
- 한정 설정 동작은 `PREPARE/CONFIRM/REVOKE_EXECUTION_CONFIGURATION` 세 종류다. PREPARE는 shell main이 원 설정창에 붙인 디렉터리 선택기에서 선택 하나를 받고, 검산된 원 native host의 전용 호출에만 전달한다. native가 최초 root와 허용된 relativeDirectory의 모든 부모·최종 cwd를 열어 물리 volume/FileId를 구하고, 신뢰하는 설정 확인 화면에 선택한 실제 위치와 프로젝트/등록·환경/명령 프로필·허용 역할을 함께 표시한다. 이때까지 저장 0. PREPARE는 기존 10초 native 호출 안에서 root부터 cwd까지 volume/FileId의 순서 있는 원 증거를 취득하고 handle을 전부 회수한다. shell main의 등록 owner가 원 호출의 결과와 선택 locator를 비공개 메모리에 보관한다. 등록당 pending ticket은 한 개이며 기한은 PREPARE 시작 단조시각+5분, 원 등록 기한, 원 owner 기한 중 최단이다. CONFIRM은 원 창/등록/epoch의 미소진 ticket을 동기 소진한 뒤 별도의 10초 이하 native 호출에서 원 locator의 각 성분을 다시 열고 원 volume/FileId 열 전체와 일치할 때만 핀을 유지한 채 기록한다. 두 호출 모두 논리 잔여기한 안에 마친다. 취소·창닫힘·만료·owner 교체는 ticket을 먼저 무효화하고 원 호출·handle 종단을 수거한다. 새 선택은 원 수거 확인 후에만 허용한다. 확정응답 또는 회수 불명 시 UNKNOWN을 보존하고 새 PREPARE/저장 재시도 0이다. 화면 표시용 경로·서버 hint·사용자가 붙여넣은 텍스트는 CONFIRM 입력이 될 수 없다. 다른 창·세션·epoch, 취소·지연·중복은 저장 0이다.
- A안 최초 지원은 동일 LOCAL Windows, `hostRef.kind=CONNECTOR_STATUS` 및 원 connector/registration fullref exact, `SOURCE_ROOT_DECLARATION` 한 개, environment가 명시한 명령 profile 중 사용자가 선택한 정확한 하나다. 기존 profile.purpose 원 값이 대소문자·공백까지 정확히 `CONTEXT_REVIEW`인 경우만 선택한다. 번역 표시명·role·대소문자 보정에서 purpose를 유추하지 않으며 새 DTO 필드는 없다. 선언/snapshot 혼용, remote·WSL·복수 root 의미, 가상/재분석·UNC·상대·장치 namespace, 고정 volume/FileId 검산 불가 시 미지원이다. workingDirectory.relativeDirectory=null이면 root 자체, 그 외에는 기존 상대 경로 검산 후 각 성분을 root 아래에서 다시 대조한다. 동일 문자열로 바뀐 경로·junction·volume 변경·하위 cwd 교체는 자동 재배정하지 않는다.
- 신규 native 보호 목적 `FN07_NORMAL_EXEC_CONFIG_V1`은 r5가 인증한 등록 root 아래 별도 namespace다. 스풀 채널·credential blob·worker 배포 manifest로 쓰지 않는다. **보호 기록**은 `{schemaVersion,purpose,configurationId,revision,previousRef,state,registrationRef,connectorRef,projectId,environmentRef,hostRef,sourceRootRef,commandProfileRef,policyRef,recipeRef,role,localRoot,localCwd,relativeDirectory,createdAt}`이다. localRoot/localCwd는 각 `{privateLocator,volumeId,fileId}`; locator와 기록 원문은 동일 등록의 기존 보호 메타데이터·기밀성/무결성 경계 안에서만 열고 서버·로그·일반 IPC에 내보내지 않는다. 외부 표시는 상태와 configurationRef뿐이다. 서버 원본의 비밀 없는 version snapshot도 같은 보호 영역에서 참조별 canonical hash를 검산하도록 저장한다. 등록 교체·root 소실 시 복원 추정 0. 최초 create-new, 개정/회수는 직전 fullref CAS와 새로운 불변 revision, 같은 revision overwrite 0. 같은 실행에 적용할 설정 head는 (등록,project,environmentRef,commandProfileRef)당 하나다. 기록/스냅샷 합산 1MiB/개정, 등록당 128개정·16MiB, 초과 시 새 설정 거절. 회수를 위해 head마다 삭제 없는 독립 폐쇄표식 한 칸을 최초에 확보한다. 불명·반쪽·보호 정착 실패는 사용 0, 자동 재작성·재설정 0. 재선택·회수 후 과거 ref를 새 실행에 쓰지 않는다.

## B. 사용 시 원 권위와 실행 직전 검산

native가 원 owner의 registration·slot과 원 grant/START/첫 SEND의 exact environmentRef·sourceScopes·session/role/bindingGeneration·dispatchAttemptRef·현재 permit·원 기한을 다시 검사한다. 제시된 환경·profile snapshot은 서버 저장 원형의 목적별 hash 규칙으로 복원하고 **원 envelope가 고정한 environmentRef → executionHostRef/sourceRoots/commandProfileRefs → 선택한 원 metadata fullref → workingDirectory.sourceRootRef**를 따라 검산한다. grant sourceScopes에서 그 root·역할에 허용된 접근을 임의 확대하지 않는다. 원 등록·slot 전용 증거로 이 그래프를 재판독할 수 없거나 같은 요청에 서로 다른 후보가 나오면 import/query/spawn 0이다. 보호된 로컬 head와 version snapshot은 서버 자원 상태의 실시간 복제본이 아니다. 원 제품 정책이 현재 head·회수 검산을 요구하는 경우에는 기존 현재성 경로가 그 사실을 검산한 범위에서만 지원한다. 단순히 오래된 snapshot을 현재로 취급하지 않는다.

로컬 설정은 설정만 지속한다. 실행 lease는 메모리에서 단일 원 시도에 발급하고 만료는 grant·slot·permit·worker·package/로컬 owner 기한의 최단이다. 불변 configRef, packageRef, cwd의 두 physical ID, 실행 환경/논리 역할·세대와 연결한다. 각 설정 호출의 물리 핸들은 호출 종료 때 닫는다. 실행 때는 root에서 cwd까지 재개방하고 각 신원·소유·쓰기/삭제 공유와 reparse를 검산하여 **CreateProcess와 resume 직전까지 경로 교체를 막는 원 핸들**을 유지한다. 검산한 경로가 다시 열리는 API라도 동일 최종 cwd를 보장할 수 없으면 효과 0. child 생애 동안 필요한 핀은 원 supervisor가 소유하고 종료/불명 절차로 회수한다. 설정 회수·개정·등록/role/grant/slot 변경·시간 경과 후 새 생성/재개 0. suspended 생성 뒤 발견하면 자기 원 handle만 회수한다. 같은 attempt의 두 번째 생성, 소실 후 다른 폴더 재탐색, UNKNOWN 후 재발급은 0이다. cwd 결박은 일반 파일 sandbox 집행 증명이 아니다.

## C. 닫힌 명령과 SDK 옵션

원 grant의 FILE sourceScopes는 Anvil의 자료/요청 귀속 제약으로 계속 검산한다. cwd의 FileId와 고정 argv/env는 Windows의 다른 파일·네트워크·도구 접근을 OS 수준에서 차단했다는 근거가 아니다. 실제 도구 요청의 CLI 권한 집행과 코딩 파일 변경 지원은 미완료로 남는다. OS sandbox 설치, AppContainer 구성, 사용자 ACL 변경은 이 후보 범위에서 제외한다.

**한 가지 역할만 지원한다.** 원 역할과 선택 profile 목적이 모두 `CONTEXT_REVIEW`인 경우에 한정한다. 이 역할의 도구 callback은 모든 호출에 원 요청과 결합한 deny를 반환한다. 실제 CLI 집행·전체 코딩 역할·파일 권한 효과를 보장하지 않는다. 다른 역할이나 실제 도구 허가·Secret이 필요한 운용은 후속이다.

고정 SDK 0.3.224용 `recipeRef`는 보호 배포 입력에 들어가는 **새 비공개 실행 recipe**의 fullref다. 편집 가능한 environment metadata 자체에 실행 규칙을 맡기지 않는다. 원 build/package owner가 SDK 버전·closure·CLI kind와 일치하는 표 하나를 패키징하고 설치 owner가 이를 검산한다. 표는 `{schemaVersion,sdkDigest,packageRefBasis,role,programSelector,profileArgs,argvTokens,baseEnv,hookEnvRules,allowedOptions}`로 닫는다. packageRefBasis는 사전 입력 ref이며 최종 ASAR/자기 hash를 역참조하지 않는다. header/최종 부모 인증은 이후 native가 수행한다.

- programSelector는 고정 CLI 이미지 또는 고정 runtime+script 중 package가 발행한 한 경우다. profile.program은 recipe의 정확한 논리 이름 한 개와 일치해야 한다. 경로·PATH basename·shell·cmd/bat의 임의 실행은 없다. profileArgs는 허용된 `LITERAL` 배열 한 개며 순서와 문자열을 완전 대조한다. 임의 literal을 CLI로 넘기지 않는다. environment.secretRefs·profile.secretSlots는 빈 배열이고 SECRET_SLOT은 미지원이다.
- argvTokens는 검토된 SDK 순서대로 작성한 고정 토큰 목록이다. 토큰 종류는 문자 그대로의 상수, 고정 SCRIPT 경로, 원 계획 SID, 원 model 문자열, 원 maxTurns 십진 정수, 원 maxBudgetUsd의 recipe 지정 SDK 표기뿐이다. 항목 하나는 항상 한 argv 원소가 된다. 선택 필드 유무는 recipe에 명시한 한 가지 조합만 허용한다. 동적 옵션명·caller extraArgs·환경 치환·쉘 분해·문자열 이어붙이기는 없다. SCRIPT는 별도 고정 런타임 program에만 script 원소를 넣고 IMAGE는 원 PE를 application으로 사용한다. native는 SDK가 전달한 command/args를 그대로 실행하지 않고 보호 recipe와 원 입력으로 다시 만든 전체 배열과 일치할 때만 Windows 인자 인코딩 후 원 executable을 호출한다. 빈 값·따옴표·역슬래시·순서 변경은 경계 시험에 포함한다.
- baseEnv는 기존 등록ㆍ제품이 보호 배포에서 고정한 비밀 없는 key/value의 닫힌 목록이다. SDK에 별도 env 객체를 명시한다. hookEnvRules는 SDK가 부가·변경하는 **확인된** 버전별 key/값 변환만 포함하며 native가 최종 전체 env를 독립 생성·대조한다. Windows 대소문자 별칭·중복키·NUL·미등록키, proxy/loader/search-path·추가 인증 입력·사용자 환경 상속은 거절한다. 필수 OS 환경·인증이 이 닫힌 집합으로 충족되지 않으면 해당 recipe는 unavailable이다. grant/Secret 자료나 부모 process.env 값에서 조용히 채우지 않는다.
- query는 원 prompt·원 signal에 묶은 AbortController·계획 sessionId·고정 cwd/env·원 모델/한도·허용한 executable/executableArgs·원 동기 spawn hook·원 deny callback만 기존 SDK 선언에 맞춰 제공한다. resume/continue/sessionStore 분기와 승인되지 않은 hook·tool·추가 옵션은 미지원이다. 공개 조회에서 확인된 Qwt→aT→cT 및 IMAGE/SCRIPT 분기는 재사용한다. **정확한 argv 전체·SDK 환경 변환·SDK 기본 CLI의 배포 원본을 현재 확보물만으로 입증할 수 없는 조합에는 실제 recipe를 발행하지 않는다.** RAM용 고정 표는 제품 allowlist로 승격하지 않는다. 2MiB/64KiB 등 기존 수송 한도는 새 실행 권위를 발급하지 않는다.

## 변경과 검수
