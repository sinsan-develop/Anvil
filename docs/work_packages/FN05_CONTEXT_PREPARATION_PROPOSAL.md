# FN05 임무 맥락 준비·저장 연결 결정안

상태: Main 제안·결정 요청. 기존 FN05/INTERFACES §10.4/DATA_MODEL §7의 상세 실행 경계이며 실제 저장·API·DB 실행 승인이 아니다.

## 1. 실제 공백과 목적

- 현재 UI04는 고정 문서·방법론·헌법·사용자 지시 원문을 각각 읽지만 임무별 불변 ContextBundle 생성·조회·누락 목록과 연결되지 않는다. 읽기 화면과 Agent 전달·이해 완료는 다르다.
- 실제 assignment_versions의 내용 확정은 정확 draft/검토/확정 ref를 보존하지만 ready/executionAuthorized/dispatchPerformed=false다. 이 확정 임무 ref를 입력으로 소비하며 임의 UUID를 검증된 임무로 승격하지 않는다.
- 예산·환경·기록 정책과 실제 Agent 전달은 미연결이다. 해당 공백을 가짜 ref/자동 허가로 채우지 않는다.
- 신규 순수 planContextText는 이미 조회된 텍스트의 hash·UTF8/분할·누락 계산만 담당한다. sourceAuthorizationVerified/budgetVerified=false이며 아직 저장/API/UI의 소비자는 없다. 기능 전체 완료가 아니다.

## 2. 권장 A: 맥락 준비 후보의 실제 저장·조회까지 연결

1. 기존 프로젝트 명령 집행 안에 buildTaskContext를 연결한다. 현재 로그인·OWNER/명시 정책·현재 client/단독 제어·명령 기한·정확 버전·idempotency/감사를 그대로 소비한다. 실행 권한/전달 허가는 생성하지 않는다.
2. 입력은 정확 확정 assignmentRef와 사용자가 명시 선택한 원문 ref/필수 항목·선택 이유다. 같은 프로젝트의 실제 저장 원문/내용 hash·격리/제외/정정·적용 헌법을 조회·대조한다. 선택이 최신 관련 지시/현재 상태의 의미를 충족한다고 자동 판정하지 않는다.
3. 목적/헌법/최신 관련 지시/결정 이유/현재 위치/실제 공백/다음 행동에 대응하는 필수 슬롯을 명시한다. 없는 항목은 MISSING으로 남기며 다른 항목이 대신했다고 자동 채우지 않는다. 예산 ref가 없거나 실검증되지 않으면 BUDGET_UNVERIFIED, 원문 선정/이해 검토 미확인도 별도 유지한다.
4. 기존 DATA_MODEL의 context_bundles/context_items와 전달 계획 metadata만 새 forward migration으로 저장한다. 원문 바이트를 DB에 중복 저장하지 않는다. 원문은 기존 보호 보관소의 exact ref/hash를 사용하고 분할 부분의 원본 ref·순서·범위·바이트 수/hash를 manifest에 결박한다. 기존 SQL·원문·확정본을 수정하지 않는다.
5. 준비 결과는 불변 버전과 missingRequired/excluded·분할 계획/미검증을 조회한다. 같은 프로젝트 회원 검사·현재 원문 접근/격리 상태를 다시 적용하며 권한 상실/원문 불가를 오래된 준비 결과로 우회하지 않는다. 일반 조회에 민감 본문을 포함하지 않는다.
6. UI04는 확정 임무 선택→원문 선택/누락 확인→명시 준비 저장→정확 후보 재조회로 연결한다. 중복 명령/오래된 응답·주체 전환·401·검증 불가를 보존하고 준비 저장을 실행 시작으로 표시하지 않는다.

## 3. 한정 승인 요청

- 코드·테스트·상세 계약 및 새 forward SQL 작성, 새 빈 격리 PG15의 합성 자료로 실제 저장/재조회·권한/CAS/replay·다른 프로젝트/구세대·원문 변조/격리/누락 핵심 검증까지다.
- 정식 개발 DB migration 적용·기존 서비스 전환·실사용자 정책 자동 부여·실제 Agent/비용·host/키/Secret/certificate·Oracle/운영은 제외한다. 원 실행 안전 거절·0012 정식 적용 차단을 우회하지 않는다.
- QA는 exact 게시 SHA 뒤 생성 전 literal 자원·owner·유효 시간·정리와 실제 부재를 별도로 등록·확인한다. 이 문서로 자원 이름이나 실행 기한을 추정하지 않는다.
- rollback은 추가 코드 후보를 중단하고 기존 서비스/정식 DB를 유지하는 것이다. 합성 QA는 등록한 exact 자원만 정리한다. 과거 불변 묶음/원문 자동 삭제·reset은 없다.

## 4. 대안과 판단

- **A 권장:** 기존 상세 계약을 소비해 실제 준비 후보 저장/조회까지 진행한다. 장점은 원문 조회 화면만 늘리는 상태를 벗어나는 것, 비용은 새 DB/API 계약·권한 검수가 필요한 점이다.
- **B:** 순수 분할 구성만 보존하고 저장/화면은 미연결로 남긴다. 새 DB/API 영향은 없으나 사용자가 임무 맥락을 준비할 수 없는 상태가 지속된다.

필요 결정은 A의 정확 범위 수용 여부다. 다음 업무 배정이나 전체 FN05/단계 완료 승인을 요청하는 문서가 아니다. 결정 전에도 기존 승인 범위의 독립 구현은 Main이 계속 선정한다.
