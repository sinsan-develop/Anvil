## 1. 실제 미완료와 이번 결정의 대상
수동 정책 입력/보관/조회·별도승인 source는 통합됐다. 그러나 runtime 프로필은 SELECTED_FILES_V1만 제공하고 정책 저장소의 전체 coverage 포트는 합성 전용이다.
그 포트를 실제 공급자로 주장하거나 선택파일 검사를 전체 검사로 승격하지 않는다.
project-inventory-composition의 각 collector는 자료·관계·이슈를 제공하지만 전체 복원 가능성/원자 snapshot/키/암호화 bundle 성공을 발급하지 않는다.
기존 전체성 missing 선언은 실현·검수한 항목별로만 해소할 수 있다. 상수 삭제로 성공을 만들지 않는다.
따라서 다음은 기존 r2의 재승인이 아니라, 아직 정의되지 않은 전체 자료 검증·암호화 묶음/복원 계약을 상세화할 범위 결정이다.

## 2. 권장 A — 전체 여정을 한 계약으로 구체화한 뒤 의존 순서대로 구현
전체 수동 백업의 대상은 사용자 선택 프로젝트·정확 정책 버전과 include 7자료군, sourceSelection NONE이다.
'전체'라는 말은 선택한 범위의 자료·역사·참조 완결성을 뜻하며, 다른 사용자 공통 자료나 선택하지 않은 소스까지 수집했다는 뜻이 아니다.
미포함 항목·타 프로젝트/외부 의존성·조회 불가 원문은 manifest에 이유를 남긴다. 복원 필수 의존성이 없으면 검증 성공을 거절한다.

| 업무 단위 | 상세 계약에서 고정할 내용 | 실제 완료 증거 |
|---|---|---|

구현 순서는 A1→A2→A3/A4→A5→A6의 실제 의존성을 따른다. A3/A4 형식은 함께 고정한다.
이 표는 완료를 작은 source PASS로 대체하는 계획이 아니다. 각 단위 source·합성 검사와 실제 DB/파일/복원/사용자 인수는 따로 남긴다.
정책 저장 가능성을 만들기 위해 A6만 먼저 연결하는 방식은 채택하지 않는다.

## 3. 상세 계약에 반드시 포함할 검수와 보류사항
- 자료 목록: 기존 composition/collector의 실제 필드·source namespace·version/hash·외부 참조와 최근 저장표의 포함 여부를 구체 표로 고정한다. 전체 DB를 무제한 SELECT하는 수집안은 금지한다.
- 일관성: Repeatable Read의 DB 범위, artifact/current 최종 검산, publish와 COMMIT 사이 불명 창, 실패 사본/원명령 보존과 재시작 조정 절차를 고정한다. 두 저장소의 원자성은 주장하지 않는다.
- 한도: 입력/출력/staging/metadata/개수/기한/실패본·저장예약은 전부 유한하고 기존 정책·profile·실제 저장한도의 최솟값을 쓴다. 임의 기본 전체10GiB 적용/무제한 fallback0.
- 암호화: 기존 후보의 AES-256-GCM은 권장 후보일 뿐 아직 채택하지 않는다. wire 형식·AAD/nonce·키 보호/이식·유실·회수와 검수안을 제시하고 의미 결정받는다. 현재 실제 key provider 없음은 그대로 표시한다.
- 비반출: Secret·계정 자체·로그인/세션 token·credential·push 구독 비밀·실제 암호화 키 바이트는 inventory/bundle/manifest에 넣지 않는다. 키는 별도 보호·이식 절차 대상이다. 필요한 비밀 없는 참조·제외 이유·재연결 metadata만 보존하고, 감사/후보/명령 원형의 민감 필드는 해당 기존 보호 계약에 맞게 분리한다. 제외한 비밀을 restored 권한으로 재생성하지 않는다.
- 안전: 현재 인증/OWNER/단독제어/명시 정책·정확 원명령/기한/일회소비·감사·최종현재성을 보존한다. 새로운 공개 API/DTO·schema·저장/approval 계약은 정확히 나열한 뒤 채택받는다.
- 합성 검사는 메모리 fixture·공개 시험용 가짜 벡터만 사용하며 실제 키나 사용자 자료를 읽지 않는다. 표식/해시만 일치하는 성공 fixture로 구현을 대신하지 않는다.
- 복원은 우선 검증만 한다. 현재 프로젝트에 적용·기존 차단 해제·실행 재개는 별도 대상이며 이번 계약 후보에 묵시 포함하지 않는다.

## 4. 대안과 필요한 결정
A(권장): 위 A1~A6 전체 상세 계약과 화면·업무 분해를 먼저 완성한다. 그 상세안의 정확 source 범위 채택 후 기존 Primary가 구현하고 Main이 검수·통합한다.
장점: 전체성/암호화/복원 정의 없이 성공 포트를 먼저 잇는 오류를 피한다. 비용: 새 데이터/공개 계약의 구체 선택을 검토해야 한다.
B: 전체 검증 계약을 미정으로 두고 현 선택파일/수동정책 source만 보존한다. 되돌릴 작업은 없지만 FN16 전체 수동 백업·작업계획 완료에는 도달하지 않는다.
Main은 A의 상세화 작업을 진행한다. PMO에는 기존 요구와 충돌하거나 빠진 검수 항목에 대한 결정·지원만 요청한다.
이 문서만으로 전체 profile 공개·실제 DB/migration·권한·키/인증서·사용자 파일 조사·서비스·Agent·backup/job/복원 실행을 승인하지 않는다.
기존 신산님 r2 직접 승인의 제외 범위를 유지하며, 추가 실행은 정확 대상/영향이 준비된 별도 승인 전까지 수행하지 않는다.
