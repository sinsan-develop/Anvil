# FN09 정상 이해 판단과 WORK 준비 연결

기준 `cea657d9`, Stage C FN09. 2026-11-24 신산님이 A안의 계약·코드·화면·미적용 SQL·합성 검증을 직접 채택했다. FN09의 정착한 사람 판단을 별도 WORK 준비에서 명시적으로 선택해 참조한다. 실제 DB·사용자 권한·키·서비스·Agent 및 운영 설정 변경은 범위 밖이다.

## 준비 저장과 이력

- 기존 `prepareExecution`의 준비 전용 입력으로 원 동일 실행의 최신 정상 적합 검토 전체 참조를 받는다. 런타임 공통 intent에 준비 전용 선택 필드를 전달하지 않는다. 기존 준비와 이전 버전 조회는 유지하며, 선택한 원 명령·내용·정책과 기존 필요한 일회 승인 소비를 같은 거래에서 결박한다.
- 현재 사람의 로그인·클라이언트·제어·정책과 동일 임무·맥락·역할 바인딩의 정확 버전·논리 세션·도구 연결·환경을 검사한다. 원 `CONTEXT_REVIEW`의 실행 ID와 세대, 준비·역할·맥락·검토 전체 참조 및 원 자료의 hash를 새 불변 WORK 준비의 증거로 보존한다. 원 범위와 정책·예산을 WORK 권한으로 상속하지 않는다.
- 정착한 원 판단의 역사 검산에는 최초 수송의 30초 기한을 다시 적용하지 않는다. 그 역사 증거와 별개로 매 새 읽기·저장은 현재 권한, 현재 승인 정책, 현재 원 역할·맥락·도구·자료 기준 및 가장 최근 검토 결과를 대조한다. 오래된 적합 판단이 최신 판단으로 바뀌면 쓸 수 없다.
- 같은 명령은 정확한 원 저장 결과를 반환하고, 같은 명령의 검토 선택이나 준비 입력이 바뀌면 거절한다. 별도 발급·다른 명령·기한 연장·원문 추가 저장은 하지 않는다. 예산·접근·능력·실행 허가는 기존 WORK 절차에서 독립 검증한다.

## 준비 화면과 시작 검산

- 준비 화면은 검증된 정확 실행·세대에서 최신 적합 판단을 사용자가 명시 선택하도록 한다. 원문을 쓰기 버퍼나 준비 이력에 넣지 않는다. 승인된 저장 결과는 준비 참조와 고정된 검토 참조를 표시한다. source가 없거나 선택을 잃은 legacy 준비는 보호 조회하되 승인된 이해 근거를 표시하지 않는다.
- 실제 WORK는 기존 새 실행 ID·별도 명령·독립 허가 규칙을 유지한다. 시작 시 준비에 정착한 원 참조를 동일 거래에서 다시 대조한다. 시점 사이에 새 검토나 권한 변경이 발생했으면 실행을 열지 않는다. 원 실행을 모드 전환하거나 정상 검토의 `executionAuthorized:false`를 실행 권리로 변경하지 않는다.

## 구현 및 검수 순서

1. 승인된 기존 준비 입력·원장·정확 승인·정산·이력의 구조를 대조하고 선택·고정·정확 재확인을 준비 저장에 연결한다. 영향 받는 저장 검산만 forward SQL로 작성한다.
2. 같은 정확 근거를 WORK 시작의 별도 현재성 검산에 연결한다. 진입에서 원 실행 ID 재사용, 최신 검토/참조 바꿈, 역할·맥락·환경·접근 조건 변경 및 승인 재사용을 거절한다.
3. UI04의 명시 선택·준비·기존 별도 승인·정확 이력 재조회를 연결한다. 첫 선택 이후 판단 변경, 문맥·인증 변경 및 전송 불명 후 원 명령 재확인 흐름을 확인한다.

최소 부정 검증은 최신 부적합·교차 scope·가짜 fullref·scope 확대·현재 권한 회수·동시 저장·승인 또는 정산 후 저장 실패의 전 거래 롤백이다. 양성은 정상 최신 적합 결과의 준비 저장 및 같은 명령의 재확인, 원 수송 기한 경과 후 새 권한으로 기존 근거를 판독하는 경우다. 뒤늦게 실패하면 새 기록을 제거하지 않고 신규 소비만 차단한다. 합성 검증은 실제 PostgreSQL·브라우저·Agent 동작으로 계산하지 않는다.
