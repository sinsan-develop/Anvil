# IX02 실제 Agent 인수 검증 준비

기준 소스 `90cddf0018e62f052999319c015d739a199b8393`. [IX02 업무 카드](INTEGRATION_WORK.md#ix02-화면실제-agent파일-변경시험-결과)의 Stage C, TC03·TC05·TC09를 검증하기 위한 실행 전 문서다. 대상 QA 프로젝트, 실행 환경, 승인 및 결과는 미확정이다. 아래 QA A와 QA B는 실행안에서 채울 구분이며 현재 생성된 프로젝트 ID가 아니다.

## 실행 전 확인 순서

1. [작업계획](../WORK_PLAN.md)과 [현재 현황](../WORK_STATUS.md)에서 UI04·UI05·UI11과 FN06·FN08·FN09·FN12의 실제 후보를 확인한다. IX01 합격이나 그 QA 프로젝트를 선행조건으로 요구하지 않는다. 두 QA 프로젝트에서 사용할 양식·방법론·설계·계획·기준 자료는 각각 이미 지원되는 경로로 준비하고, 최초 실행 전에 고정 전체 참조를 기록한다.
2. [개발환경](../DEVELOPMENT_ENVIRONMENT.md)에 맞는 신규 격리 대상과 합성 자료를 확정한다. A와 B는 서로 다른 프로젝트, 원본 저장소와 쓰기 루트, 실행·세션 식별자 및 산출물 위치를 갖는다. B가 A의 결과나 승인에 의존하지 않도록 각 실행의 사용자·기기·등록·제어·범위를 대조한다. Anvil 제품 소스와 기존 프로젝트에는 두 임무의 쓰기 범위를 부여하지 않는다.
3. UI11의 현재 등록·허용 동작·환경에 결박한 실제 Claude Code 경로를 먼저 확인한다. SDK `0.3.224`는 기존에 대조한 공개 소스 기준이다. 실제 설치된 SDK, Claude Code 제품·버전, 선택된 모델·환경은 실행안의 허용된 확인에서 원 출처와 함께 수거한다. [고정 SDK 원문 확인 기록](../04_test_reports/AV3/FN07_PINNED_SDK_SPAWN_SOURCE_READ_20261106.md)과 런타임 관측을 구분한다. 실제 선택을 확인하지 못하면 기본값으로 채우지 않는다.
4. UI04에서 정확 임무·책임 세션과 기준 맥락을 조회한다. FN09에서 목적·헌법·최신 지시·완료 내역·다음 임무 버전과 수신·이해 증거를 대조한다. UI11의 설정 표기나 준비 자료만으로 사용 가능한 실행 권위를 추론하지 않는다. 현재 등록·실행 세대·환경·허가·소스/Writer의 실제 증거와 FN08의 기존 정상 전달 경로가 확인될 때만 수행 임무로 이어간다.
5. FN12의 [보호 실행 증거 계약](../contracts/FN12_NORMAL_EXECUTION_EVIDENCE.md)에 따라 개별 명령의 원 소유 핸들·종료와 같은 호출의 환경·커밋·산출물을 직접 관측하고, 서버에서 고정 결과·증거를 재조회할 수 있는지 확인한다. [등록 시험 명령 후보](../contracts/FN12_REGISTERED_TEST_COMMAND_CAPTURE_CANDIDATE.md)는 필요한 경계의 설계 근거다. 시험 정의나 합성 모델로 실행을 발급하지 않는다. 미연결이면 해당 실제 검사는 미실행으로 표시하고 결손을 담당 기능에 돌린다.

### 기준선 증거의 범위

| 확인 근거 | 실제 인수에서 남은 확인 |
| --- | --- |
| SDK `0.3.224` 공개 원문과 고정 계약의 선행 확인 | 지정 설치본·실제 모델·실제 환경, 현재 등록/실행과 연결된 소유 세션 |
| UI/보호 조회·정규화·재확인의 소스·합성 결과와 과거 한정 FN12 직접보고 저장 시험 | 실제 브라우저→Agent 수신·수행→정상 실행기 직접 관측→검수와 참조 재조회 |
| FN12 실행 증거 원형·합성 시험, 등록 시험 명령의 효과 없는 모델 | 개별 명령 시작/종료 관측 포트·보호 저장·서버 재조회, 목적 권위와 현재 범위 |

## QA A — 기존 Claude Code의 제한 코딩과 시험

작업 예시는 별도 합성 저장소에서 ASCII 영문 상태값 `READY`의 앞뒤 공백을 제거한 뒤 같은 상태로 인식하도록 기존 단일 함수와 그 단일 시험 파일을 고치는 것이다. 실행안에는 실제 두 파일, 사전 커밋·본문 해시, 변경 금지 범위, 예상 diff와 시험을 고정한다. AF05에는 공백 포함 정상 입력과 기존 미지원 입력 보존의 기대값, 고정 실행 인자, 재현 위치를 기록한다. 초안의 예시만으로 파일 쓰기나 명령 실행을 발급하지 않는다.

| 순서 | 관측할 행동과 남길 자료 |
| --- | --- |
| A1. 고정 기준 | QA A 프로젝트 ID, 저장소 전체 커밋, 계획·설계 전체 참조, 업무 코드와 확정 임무 전체 참조, AF05 원문 전체 참조·TC ID·고정 시험 명세 digest·기대 결과를 기록한다. 운영자 확인과 실제 도구·모델·환경 확인을 분리한다. |
| A2. 화면 지시와 이해 대조 | UI04에서 기존 책임 세션을 선택하고 목적·헌법·최신 지시·완료·다음 임무의 정확 묶음을 보낸다. 업무·역할·등록·준비·맥락 전체 참조, 자료별 전송/수신과 불충분 여부, 이해 응답과 사람의 대조 판정을 수거한다. 수신 증거 또는 필수 이해 근거가 없으면 코딩 임무를 보내지 않는다. |
| A3. 제한 실행 | 사용자가 명시 지시하고 UI04에서 수신과 실행을 구분해 확인한다. 원 명령 ID/봉투 해시, 등록·허가·로컬 시도, 같은 프로젝트·실행 ID/세대, Agent 세션, 수신 근거와 시작·종료 확인을 연결한다. 작업 디렉터리, 쓸 수 있는 두 파일, 외부 접근 제한과 시간·자원·비용 한도를 관측한다. |
| A4. 파일·시험 | 사전 커밋과 결과 diff 및 허용된 변경 파일별 전후 해시를 수거한다. 확정 AF05의 지정 시험을 기존 적격 경로에서 수행한 경우 해당 개별 호출의 원 참조, 정확 argv 또는 보호 원문 참조 및 digest, 시작·종료/exit, 환경 지문·전체 commit, 산출물 원 참조·길이·해시를 같은 등록·실행·세대에서 대조한다. 허용 범위 밖 diff가 있으면 실패로 기록한다. |
| A5. 제출과 검수 | UI05에 나타난 수행자 제출 ref·주장, 보호 실행기 관측 ref, 시험 산출물 ref, 검수자의 별도 판정과 근거 ref를 각각 수거한다. 범위·위험·근거 누락에 해당하는 경우만 독립 재현하고, 재사용하는 시험은 기존 동일 명령·환경·커밋·산출물 및 검수 근거를 명시한다. 참조가 다르거나 관측이 빠진 시험은 검수 성공으로 올리지 않는다. |
| A6. 재조회 | UI06의 고정 설계 항목 또는 계획 업무에서 정확 결과·검수·AF05를 다시 찾고 해당 자료의 전체 참조 및 시각을 UI05와 대조한다. 화면 캡처와 API/보호 조회의 일치, 원 명령 반복 효과와 결과 저장 횟수를 확인한다. |

## QA B — 같은 Agent 제품의 설계·작업계획 제안

QA B에는 읽기 가능한 합성 요구사항과 [문서작성 공통기준](../design/문서작성_공통기준.md)의 고정 버전을 공급한다. 허용 산출물은 QA B 전용 제안이다. 상세 화면의 목적·상태·동작, 화면/기능/연결 작업의 별도 ID와 선후행, 위임 범위·완료 기준·검수/시험, 변경 이유와 원 설계·업무 간 추적을 요구한다. B의 실제 제품·버전·모델·환경은 별도로 기록해 A와 같은 Agent 제품인지 확인한다. B에 소스 구현·코딩 시험·제품 반영 권위를 부여하지 않는다.

| 순서 | 관측할 행동과 남길 자료 |
| --- | --- |
| B1. 별도 대상 확정 | QA B 프로젝트 ID, 기준 요구사항·공통기준·적용 방법론·허용 제안 범위의 전체 참조, 전달 전 문서·계획의 상태/버전 및 소스 상태를 기록한다. |
| B2. 실제 작성 지시 | UI04에서 별도 정확 작성 임무·책임 세션으로 맥락 전달 및 이해 확인을 수행한다. 원 지시·수신 ref, 명령과 실행 ID/세대, Agent 세션 및 해당 쓰기 범위를 보관한다. |
| B3. 보호 제안 수거 | 제안의 ID·고정 버전/본문 해시, 상세 화면, UI/기능/연결 작업 ID와 선행, 위임/검수/시험 기준, 변경 전후/이유/출처를 확인한다. 사용자에게 빠진 항목과 불명확한 연결이 드러나는지 검사한다. 제안과 원자료의 보호 조회를 따로 수행한다. |
| B4. 사람 검토 | 권한 있는 HUMAN이 원 제안과 누락을 읽고 검토 결과·이유·담당·검토 시각을 남긴다. 검토 이력은 같은 제안 버전·해시를 가리켜야 한다. 빠진 항목은 보완 대상으로 남긴다. 검토자는 자동 생성 작업을 실행하거나 제안을 기준으로 확정하지 않는다. |
| B5. 상태 대조 | 제안과 검토를 보호 재조회하고, 전후 소스·문서/계획 기준 버전과 명령/실행 이력을 대조한다. 구현 명령, 기준 확정·적용, 자동 수락이 발생하면 실패다. |

## 음성 시나리오와 판정

| 확인할 조건 | 기대 관측 |
| --- | --- |
| 제출자가 완료를 주장하나 시험 exit·산출물 중 하나가 빠짐, 다른 호출·세대·환경 또는 hash | 주장만 유지하고 증거 부족을 표시한다. 제출 승인이나 업무 완료 판정으로 진행하지 않는다. SDK stdout·자식 종료·ACK로 개별 명령 exit나 파일 변경을 채우지 않는다. |
| 지시 미수신, 도구 명시 거부, 원인 미확인 또는 한도 초과 | 원 명령의 수신 기록·명시 오류·한도 근거·불명을 각각 판독한다. 수신 전에는 미수신, 원인 근거가 없으면 미확인으로 남긴다. 한도 또는 권한 거절의 실제 부작용을 확인한다. ACK나 정상 응답을 만들어 넣지 않는다. |
| 정상 장시간 명령 | 동일 실행 관측의 시각과 원 한도에서 진행을 확인하고 자동 실패나 자동 재실행 여부를 검사한다. 사용자에게 멈춤·명시 실패·진행을 구별해 표시한다. |
| 다른 프로젝트 ID/참조, 범위 밖 경로, 합성 민감 표식, 폐기·만료된 권위 | 거절과 선택적 정보 비노출, 외부 쓰기·출력 노출·실행 효과 0을 확인한다. 실제 비밀이나 기존 프로젝트 파일은 음성 입력으로 사용하지 않는다. |
| B 상세 화면/연결 업무/검수 기준 누락, 또는 늦은 응답으로 다른 제안을 읽음 | 해당 제안에 누락을 표시한다. 교차 참조에서 다른 문서를 열거나, 제안을 자동 확정·적용하거나, 코딩을 시작하면 실패다. |

두 프로젝트에서 각 해당 절차와 음성 증거를 확인하고 A의 화면 지시→실제 세션/실행→파일·시험→총괄 판정, B의 실제 제안→누락 검사→HUMAN 검토→재조회가 연결되어야 IX02 합격으로 기록한다. 실제 Agent를 호출하지 못하거나 실제 보호 근거가 빠진 항목은 미실행/미확인으로 남긴다. 수행자 주장, SDK 출력, 합성 도구 응답, 테스트 fixture는 각 출처로만 기록한다.

## 별도 실행안에 고정할 항목

- **동결 대상과 실행 승인**. 실행안 ID·버전·지문과 직접 승인 참조, 실행 담당, 대상 A/B와 양쪽 QA 프로젝트 ID 또는 신규 생성 규칙을 기록한다. 시작·만료·시도 횟수·재접수 조건, exact Anvil 전체 Git SHA와 build/의존성/적용 SQL manifest 지문, 양쪽 QA 소스의 확정 기준 SHA와 증거 수거 ref를 고정한다.
- **환경과 자원**. 대상 호스트·계정/실행 사용자, 실제 설치 도구·모델을 확인할 경로와 정확 조회/실행 명령을 명시한다. 등록 실행기·환경·테스트 프로필과 권위 범위, 신규 격리 DB/네트워크/프로세스/저장 루트·출력·수거 위치와 소유자/라벨/원 ID 검산, 고정 시작 디렉터리와 읽기·쓰기 허용 파일, 네트워크 허용 대상·외부 전송/비용·credential 사용 경계를 고정한다. 비밀 원문은 실행안과 증거에 넣지 않는다.
- **한도와 중단**. 전체 창과 A/B 각각의 세션·개별 명령 시간, 최대 실행/요청·비용·CPU/메모리/저장·산출물 수와 크기 및 증거 조회·출력 상한을 기재한다. 원 등록·권한·허가 기한이 더 짧으면 기존 최단 경계를 적용한다. 여기서 실제 수치나 추가 허가를 발행하지 않는다.
- **보존·수거·정리**. 실행 전 원본과 소유를 대조하고, 종료 후 프로젝트·명령·등록·프로세스·파일·산출물의 실제 식별자 및 정리 전후를 manifest에 결박한다. 완료 상태가 확정되고 새 격리 자원의 소유·정리 허가가 확인된 경우에만 정리한다. 실패·부분 효과·응답 유실 또는 대상/종료 불명은 해당 상태와 원 증거를 보존한다. 후속 조회·재시도·자동 삭제의 허용 여부는 동결 실행안의 범위를 따른다. 불명 상태를 새 명령·세션으로 조용히 대체하지 않는다.

이 문서에는 요구 증거와 판정법을 기록했다. QA 프로젝트 생성, 실제 환경 조회, 명령·시험·Agent 실행, 권한·DB·서비스 변경, 시험 결과 기록은 이 문서 작성 범위에서 수행하지 않았다.
