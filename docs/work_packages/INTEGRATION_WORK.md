# Anvil v3 준비·통합 검수 업무 카드

상위 계약: [작업계획서](../WORK_PLAN.md). 실제 상태는 WORK_STATUS와 계획 등록부를 따른다. 준비 업무를 기능 구현으로, 통합 시나리오 작성만으로 실제 통과로 계산하지 않는다. 공통 위임·기록·QA·rollback 규칙을 상속한다.

## P01 상세 클릭형 동작·상태·화면 확정

- **목적/설계:** §11, INT-06. 정적 그림을 실제 사용 흐름·정상/실패/권한 상태까지 검토 가능한 시안으로 만든다.
- **입력/선행:** 현재 상세 설계·S01~S14 정적 시안·인터뷰 합의·문서 작성 공통 기준. 사용자의 계획 작성 요청을 미작성 클릭형 시안 승인으로 간주하지 않음.
- **범위/파일:** `docs/design/prototypes/core-workflow/index.html`, `README.md`, 상태별 시안/대표 캡처·검토 기록. 실제 Agent·DB·외부 요청 없는 설계용이며 제품 코드 생성 제외.
- **수행:** 프로젝트 생성→방법론→문서/계획추적→지시→승인/미수행→교체/이해대조→재개를 연결한다. 모든 S화면의 진입/뒤로/주요 버튼·필수 입력·오류/빈상태/권한·정지 미확인을 시안 상태로 확인한다. 공통 문서 양식에서 화면/FN업무의 관계도 보여준다.
- **RED/GREEN:** `critical_path_has_no_dead_end`, `unsafe_stop_no_resume`, `document_save_not_execute`, `mobile_same_request`, `all_screens_have_normal_and_relevant_error_states`. 시안 클릭으로 실제 서비스 호출이 일어나면 실패다.
- **검수:** 사용자가 브라우저에서 핵심 흐름·상태를 검토하고 화면별 승인/수정/보류를 기록. README에 여는 방법·예시 자료·작동/미작동을 명시. 기준 동작을 설계 ID와 연결.
- **산출물/후속:** 확정 화면·행동/상태 목록·결정·원문 참조·설계 hash. 바뀐 설계가 계획에 영향을 주면 해당 업무 카드만 개정. 승인 전 해당 동작 구현 배정 금지.

## P02 기술·외부 지원·데이터/API·문서 양식 계약 확정

- **목적/설계:** §9,10,12,13.4. 작업자가 기술/인터페이스를 제각각 추측하지 않도록 실행 계약을 고정한다.
- **입력/선행:** 현재 설계·계획·[문서 작성 공통 기준](../design/문서작성_공통기준.md). 읽기 조사로 기존 보관 자산 재사용 가능성 확인, 기존 코드를 정본으로 복원하지 않음.
- **범위/파일:** `docs/contracts/TECH_DECISIONS.md`, `FILE_MAP.md`, `INTERFACES.md`, `CAPABILITIES.md`, `DATA_MODEL.md`. 구현/새 서비스/외부 비용은 제외. 연결 실제 변경 검증은 별도 승인 범위 대조 후 FN06/07에서 수행.
- **수행:** 서버·DB/파일·웹·Windows실행기·설치형·인증/보호저장소 선택안과 근거, 첫/둘째 실제 코딩 Agent의 공식 연동 방식·버전별 기능·원격제어 한계, 총괄 판단용 연결을 구분한다. 최신 공식 자료와 설치된 버전을 실제 확인한다.
- **계약 산출:** 각 FN 연산→실제 endpoint/함수·입출력 schema·필수 필드·권한·오류·원자성/중복 규칙·pagination/이벤트. 각 UI action→소비 연산. 논리 개체→테이블/파일·보존·암호화·migration 영향. 책임 폴더→정확 파일·시험 파일·공유 소유자. 공통 설계/계획 양식 버전·승인 규칙도 고정.
- **추가 결정:** 대표 대화/첨부/인계 표본으로 성능·손실 지표 측정안을 작성하고 수치/환경/측정방법을 사용자 검토에 올린다. 백업 위치/주기/보관·단절 한도를 제안·확정한다. 임의 수치 합격/무제한 기본값 금지.
- **검수:** UI15개/FN18개가 소비·생산하는 연산/모델/오류/파일의 정의 누락0, 서로 다른 명칭 충돌0. 외부 미지원/미확인과 실제 지원 구분. 권한/데이터/비용/제품범위 변경은 사용자 결정 기록.
- **P02 필수 능력표:** CAPABILITIES §7의 필수6능력×후보 도구 표를 완료 산출물로 고정한다. 공식 근거/정확 버전 적합성·문서 판정(경로 후보/미확인/미지원)·통제 한계·실측 상태/근거를 분리하고 빈칸 없이 기록한다. 미확인도 유효한 조사 결과이나 실행 허가는 아니다. 실제 도구/세션·유료/쓰기·중지 회수 시험은 FN06/07에서 수행한다.
- **산출/후속:** 실제 배정 패킷에 복사 가능한 명세. 계약이 없는 업무는 구현 시작 불가이나 무관한 확정 설계/화면 검토는 계속한다. 기술 선택은 공개 API/지속 데이터 변경 실행 승인을 대신하지 않음.
- **검토 보완:** THREAT_MODEL의 서버→PC·등록/인증·명령/경로/OS 소유·spool/비밀/용량 경계와 책임/필수 시험, TRACEABILITY의 F/FN/UI/IX/TC 관계, BASELINE_MANIFEST의 관측 hash/승인 범위 구분을 포함한다. P02의 공식/설치 지원만으로 actual go 판정을 내리지 않는다. 실제 FN06의 필수 능력 미확인/미지원은 해당 변경 역할을 차단하고 대안·정확한 사용자 결정으로 연결하며 독립 코어 개발은 계속한다. 문서 업무를 실제 유료/쓰기 시험으로 자동 확대하지 않는다.

## P03 개발 기준선·실행 명령·시험 자료 준비

- **목적/설계:** §12~13 및 PMO 환경 규칙. 승인 뒤 실제로 같은 기준에서 실행·검수할 최소 개발 환경을 마련한다.
- **입력/선행:** P01,P02의 수용된 결과, 구현 시작 승인. 지금 계획 작성 단계에서는 실행하지 않음.
- **범위/파일:** `docs/DEVELOPMENT_ENVIRONMENT.md`, `docs/contracts/COMMAND_MAP.md`, 승인 범위의 최소 build/test 설정·QA seed/reset. 새 서버 설치·서비스 교체·원격 이력 초기화는 제외.
- **수행:** 실제 Git root/branch/HEAD·dirty소유·비어 있는 원격·복구 자료를 대조해 신규 개발 기준선/branch 처리안을 확정. 제품 개발·QA·보존 대상과 서비스/DB 이름·공통 port·비밀 참조를 명시. 읽기 확인과 실제 변경을 구분한다.
- **명령표:** UI/FN/IX 각 ID에 설치 필요 여부·실행 cwd·정확 명령·정상 결과·실패 시 확인 위치·테스트 대상·증거·정리를 연결. 도구 버전·lockfile 고정, 검증 자체를 위한 대규모 별도 프레임워크 제작 금지.
- **공급망 준비:** 제품 의존 패키지의 출처·정확 버전/lockfile·설치 스크립트 실행 필요/영향을 검토한다. FN18에 전달할 산출물 hash·업데이트 신뢰/서명 확인 기준은 P02 결정과 결박하고 근거 없는 자동 최신화·무검토 스크립트 실행을 준비 완료로 처리하지 않는다. 실제 설치/키·인증서 변경은 해당 승인 경계 대조 후다.
- **QA:** 소유자/조회자/인수자·프로젝트2개, 제한된 시험 소스, 정상/실패용 문서·방법론·명령/승인·인계자료의 seed/reset 규칙. 비밀은 합성/보호 참조, 실 운영 자료 복제 금지.
- **검수:** 새 검증 환경에서 문서대로 최소 실행/저장/조회·단위/화면 명령을 재현. 실제 외부 미연결은 별도 표시. 기존 서비스 영향0·정확 임시자원 정리와 재실행 가능성 확인.
- **산출/후속:** ENVIRONMENT_READY 또는 외부 미확인 포함 판정·정확 명령표·배정 기준. 승인된 계획 내 DB schema·migration·지속 데이터 변경은 계획 승인으로 진행하며 별도 DB 승인을 다시 요청하지 않는다. 새 자격증명·인증/권한·Secret·계획 밖 DB 변경·서비스 반영 등 별도 경계는 그 영향 항목만 분리해 필요한 승인을 요청한다. 원격 push는 기존 승인된 저장소·branch 범위로 수행한다.
- **기준선 보완:** 새 문서의 미커밋·기존 정리 삭제·사용자 자료를 파일별로 구분해 정확한 Stage 기준선 commit 범위를 먼저 확인한다. archive branch를 임의 생성하거나 기존 이력을 reset/재생성하지 않는다. 로컬 문서 hash 관측과 Git commit·원격 게시·실제 사용자 승인을 별도 증거로 기록한다. 등록되지 않은 실제 port/DB/인증/보호 경로를 추측해 설정하지 않는다.

## IX01 방법론→프로젝트→문서→계획·지식 연결

- **범위/설계:** Stage B, TC01,02,05,08,14. 선행 UI01~03,UI06,UI10/FN01~05,FN11. 제품 문서 작성 공통 양식도 포함한다. FN04→FN11 간접 선행을 직접 명시한 것이며 새 기능 선행을 만드는 뜻이 아니다.
- **파일/입출력:** `tests/integration/IX01/`, `tests/browser/IX01/`, 결과 폴더. 결과는 생성한 실제 프로젝트/방법론/문서·설계/계획/지식 ID와 재조회 근거. 결함 수정은 소유 UI/FN에 돌려보냄.
- **검수 절차:** ①문서 가져오기+대화 보완 ②사람/분기/합류/재작업 방법론 저장·확정 ③프로젝트 적용 ④상세 화면 포함 설계 확정 ⑤화면/기능/연결 작업계획 작성 ⑥설계위치에서 작업/시험 왕복 ⑦결정이유·원문 저장/검색 ⑧화면/서비스 재시작 뒤 재조회.
- **음성/RED:** 외부 문서 명령·지원불가 형식·동시 편집·미확정 설계·연결없는 작업·타 프로젝트 조회. 실제 실행 자동 시작0·미확인 PASS0·원문 손실0.
- **조기 보안 필수 검수:** QA 프로젝트 두 개와 허가가 다른 사용자를 사용해 목록/직접 프로젝트 ID/문서·첨부 ID/검색의 교차 접근을 거절하고 허가 없는 이름·건수·존재를 노출하지 않는지 확인한다. 같은 화면에서 정상 변경→세션 만료 후 직접 변경 거절→현재와 다른/회수된 초기 제어 세대의 직접 변경 거절을 서버 응답·저장 전후·부작용0으로 대조한다. FN01/FN11의 기존 인증/초기 제어 기반으로 검수하며 FN15의 사람/기기 인수를 미리 구현하지 않는다. IX05는 후속 인계/PC·모바일 경계에서 이를 다시 확인한다.
- **합격:** 시스템 내장 선택·적용, 내장 복사·수정, 사용자 직접 정의의 세 경로를 실제 저장/재조회하며 적용 버전·출처를 확인한다. 확정된 내장 종류마다 필수 문서·승인/보완 경로를 검사하고 업데이트로 기존 프로젝트가 바뀌지 않아야 한다. 실제 영속 자료와 화면 내용/버전/추적 일치, 문서 양식에 위임/검수 기준 존재, 무승인 명령0. 디자인/목업만 통과하면 실패.
- **증거/정리:** 각 단계 API/저장 결과·핵심 캡처·TC별 판정·QA ID 정리. 이후 IX02에 넘길 확정 기준과 프로젝트 checkpoint를 보존.

## IX02 화면→실제 Agent→파일 변경·시험 결과

- **범위/설계:** Stage C, TC03,05,09. 선행 UI04,UI05,UI11/FN06,FN08,FN09,FN12. 실제 Agent1종이 필수.
- **파일:** `tests/integration/IX02/`, `tests/browser/IX02/`와 증거. 실제 coding 임무는 승인된 작은 QA 프로젝트에서 수행, Anvil 제품 자체를 임의 수정하게 하지 않음.
- **검수 절차:** ①실제 도구/모델/버전·환경 확인 ②목적·헌법·최신지시·이미 완료/다음 임무 전달 ③이해 대조 ④화면에서 제한 기능 구현 임무 지시 ⑤수신/실행·파일diff/시험 결과 수집 ⑥제출과 총괄검수 분리 ⑦문서/추적에서 결과 재조회. 추가로 다른 QA 프로젝트의 설계/작업계획 작성 임무를 같은 공통 기준으로 실제 Agent에게 전달→상세 화면/화면·기능·연결 업무/위임·검수 조건이 담긴 문서 제안 수집→누락검사/사용자 검토를 확인한다. 제안 생성이 제품 구현이나 자동 확정으로 이어지면 실패다.
- **음성/RED:** 의도적으로 결과 증거 일부 누락, 미수신·도구 명시 거부·원인 미확인·한도·긴 정상 명령을 구별. 비밀/범위밖 경로 차단. 가짜 모델 답변/하드코딩 결과로 대체 금지.
- **합격:** 화면 지시→실제 세션/실행ID→실제 파일·시험→총괄 판정이 연결. 제품 자체 coding engine이 아닌 기존 Agent 수행의 증거.
- **증거/정리:** exact Anvil commit·Agent 제품/버전·명령·QA diff·기준/실제 결과·미확인. 생성된 QA 실행·프로세스·파일의 보존/정리 manifest.
