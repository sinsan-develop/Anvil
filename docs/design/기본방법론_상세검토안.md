# 기본 내장 방법론 3종 상세 검토안 — P01

2026-10-15 / 종류는 신산님 확정 / 아래 절차·양식·검수 구성은 사용자 검토 전 상세 제안. 특정 외부 표준의 완전한 인증·준수를 주장하지 않는다.

## 1. 공통 적용 규칙

사용자는 시스템 기본본 그대로 사용, 복사·수정, 직접 정의 중 선택한다. 기본본은 문서 제목 목록이 아니라 **절차·문서 양식·책임 역할·입출력·완료 기준·승인·보완 경로**를 함께 제공한다. 프로젝트 적용 시 특정 버전을 고정한다.

모든 종류에 프로젝트 목적·헌법·최신 지시·개발환경·권한을 입력한다. 총괄은 Anvil 원본에서 이를 전달하고 각 단계책임자는 직접/하위 Agent 작업 방식을 정한다. 사람의 확인은 Agent 완료 선언으로 대체하지 않는다. 담당 Agent·모델·계정은 내장하지 않는다.

모든 문서는 [문서 작성 공통 기준](문서작성_공통기준.md)을 적용한다. 상세 화면 → 화면/기능/연결 계획 → 실제 코드/시험 → 검수와 변경 역사가 연결돼야 한다. 개발환경 정의·테스트계획·상세 현황·인계 기록은 방법론 종류에 관계없이 필요하다.

자동/건별은 각 방법론에서 선택 가능하다. 자동도 지정 승인 지점·권한·한도를 넘지 못한다. 실제 배포는 ‘배포 준비’ 결과와 별도 승인·계획으로 분리한다.

## 2. SYS-M01 구조적 방법론 v1 제안

분해한 기능·처리·데이터 흐름과 실제 사용자 화면의 연결을 중심으로 진행한다. 순차 기본 흐름을 제공하되 검토 실패의 보완 경로를 명시한다.

| 단계/책임 역할 | 입력 | 산출물·완료 조건 | 다음/보완 |
|---|---|---|---|
| ST01 요구·현행 분석 / 분석 책임자 | 목적·사용자·요구·기존 소스/자료 | 요구 ID·범위·현재/목표 흐름·완료/제외. 사용자 확인 | 미합의 요구만 보완 |
| ST02 기능·데이터 분석 / 분석 책임자 | 확정 요구 | 기능 분해·입출력·처리 흐름·데이터 정의·예외·요구 연결 | 누락/모순은 ST01/02 |
| ST03 상세 설계·화면 / 설계 책임자 | 분석 결과 | 처리 단위·저장/조회·상세 화면/상태·권한·인터페이스·설계 ID. 사용자 화면/설계 확인 | 화면만 있고 처리/데이터 미연결이면 보완 |
| ST04 개발·시험계획 / 계획 책임자 | 확정 설계·환경 | 화면/기능/연결 업무·의존·담당·검증/검수·복구. 사용자 계획 확인 | 누락 설계는 ST03 |
| ST05 구현 / 구현 책임자 | 고정 기준·임무 | 허용 코드·실제 저장/조회·자체 핵심 정상/실패 증거·현황 | 부족 항목만 재작업 |
| ST06 검토·통합 시험 / 검토·시험 역할 | 결과·시험계획 | 사용자 흐름·처리/데이터 정합·권한·변경 영향 확인, 제출≠합격 | 구현 결함 ST05 / 설계 결함 변경절차 |
| ST07 준비·사용자 확인 / 총괄·사용자 | 검수 근거·잔여 | 실제 가능/부분/미구현/미확인·사용 방법·배포 준비. 사용자 완료 확인 | 미충족 상태 공개·해당 단계 보완 |

기본 양식: 요구사항, 기능/처리 분해표, 데이터 흐름/정의, 상세 설계·화면, 개발/테스트계획, 환경/권한, 작업현황·결과/검수, 변경·인계. 흐름도 표기법·상세 수준은 프로젝트 규모에 맞춰 검토한다. 필요 없는 그림의 개수로 완료를 판단하지 않는다.

## 3. SYS-M02 객체지향 방법론 v1 제안

사용자의 시나리오에서 필요한 객체의 책임·상호작용·데이터 수명과 화면 행동을 도출한다. 특정 언어·설계 패턴·다이어그램 전체 작성을 강제하지 않는다.

| 단계/책임 역할 | 입력 | 산출물·완료 조건 | 다음/보완 |
|---|---|---|---|
| OO01 목적·사용 시나리오 / 분석 책임자 | 목적·사용자·헌법·요구 | 사용자/권한·정상/실패 시나리오·수용 기준·범위. 사용자 확인 | 모호한 사용자 행동 보완 |
| OO02 객체·책임 분석 / 분석 책임자 | 확정 시나리오 | 주요 개념/객체·책임·관계·상태/수명·업무 규칙, 요구 추적 | 시나리오 누락은 OO01 |
| OO03 협력·상세 설계·화면 / 설계 책임자 | 객체 분석·환경 | 객체 상호작용/인터페이스·저장/조회·상태 전이·권한·상세 화면·ID. 사용자 확인 | 과도한 추상화/미연결은 보완 |
| OO04 개발·시험계획 / 계획 책임자 | 확정 설계 | 화면/기능/연결 작업, 책임 경계·의존, 객체/서비스와 사용자 흐름 시험·검수. 사용자 확인 | 기준 부족은 OO03 |

| OO07 준비·사용자 확인 / 총괄·사용자 | 검수·잔여 | 사용 방법·기능4상태·남은 위험·배포 준비·사용자 완료 확인 | 미충족을 완료로 숨기지 않음 |

기본 양식: 요구/사용 시나리오, 객체·책임·관계, 상호작용/상태, 상세 설계·화면, 개발/테스트계획, 환경/권한, 작업현황·검수·변경·인계. 클래스 수/패턴 수가 아니라 실제 시나리오와 책임/데이터 정합으로 검수한다.

## 4. SYS-M03 애자일 방법론 v1 제안

전체 목적·요구 목록을 유지하면서 사용 가능한 증분을 반복 개발·검토한다. 애자일을 ‘설계/문서/시험 생략’으로 해석하지 않는다. Scrum의 고정 역할·기간·행사를 자동 강제하지 않으며 반복 길이·한도는 프로젝트 설정이다.

| 단계/책임 역할 | 입력 | 산출물·완료 조건 | 다음/보완 |
|---|---|---|---|
| AG01 제품 방향·요구 목록 / 총괄·사용자 | 목적·사용자·범위·헌법 | 요구 ID·가치/우선순위·수용/제외·전체 미구현 목록. 사용자 확인 | 새 요구는 버전/결정 기록 |
| AG02 이번 반복 선택 / 총괄·단계책임자 | 요구 목록·이전 결과·자원 | 반복 목표·선택/제외·수용 기준·의존·환경/한도. 사용자 범위 확인 | 무리한 범위는 분할/재선택 |
| AG03 필요한 상세 설계·화면 / 설계 책임자 | 선택 요구·기존 설계 | 변경 부분 상세 화면/처리/데이터/예외·설계 ID·영향. 사용자 확인 | 기존 확정 설계는 무조건 재작성 안 함 |
| AG04 반복 작업·시험계획 / 계획 책임자 | 확정 설계·반복 목표 | 화면/기능/연결 업무·담당·검증/검수. 사용자 계획 확인 | 입력 부족은 AG02/03 |
| AG05 구현·관련 시험 / 구현 책임자 | 승인 임무 | 실제 사용 가능한 연결·증거·상태·잔여 | 실패 조건 보완, 무관 업무 지속 |
| AG06 증분 검토 / 총괄·사용자 | 실제 결과·수용 기준 | 실제 사용·피드백·미완료·시험/위험 구분. 증분 수용 | 결함은 보완/다음 반복 여부 명시 |
| AG07 개선·다음 반복/전체 확인 / 총괄·사용자 | 피드백·전체 요구·이력 | 방법 개선 제안·다음 우선순위·전체 누락 대조 | AG02 반복 / 전체 범위 충족 후 사용자 완료 |

기본 양식: 제품 목적/요구 목록, 반복 목표/선택, 해당 상세 설계·화면, 반복 작업/시험계획, 환경·현황·증분 결과·피드백·개선 제안·변경/인계. 반복 종료 시 미완료를 삭제하거나 전체 완료로 표시하지 않는다.

## 5. 이번 검토 항목

- 세 기본본의 절차·문서·사용자 확인 지점이 실제 개발 방식에 맞는가.
- 기본본 그대로/복사 수정/직접 작성의 구분이 명확한가.
- 총괄·단계책임자·하위 Agent, 자동/건별, 상세 현황·검수·교체/인계 기준이 어느 방법론에서도 유지되는가.
- 너무 많은 의무 문서를 기계적으로 반복시키거나, 반대로 필요한 설계·기능·검증을 생략하지 않는가.

검토 결과는 대화의 사용자 지시를 근거로 기록한다. 시안의 선택·버튼 클릭만으로 실제 설계 승인·작업 실행·기존 프로젝트 변경을 처리하지 않는다.
