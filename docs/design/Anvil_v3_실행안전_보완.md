# Anvil v3 실행 안전과 검수 상세 보완

> **2026-10-16 이력 전환:** 신산님의 설계서·작업계획서 본문 수정 지시에 따라 아래 r1 내용을 설계 r6 §2.3/4.3.1/6.2/7.3~4/8/9.1.1/9.3/10/12/13과 계획 r5 §2.2~3·업무 카드에 직접 통합했다. 현행 실행 기준은 [설계 본문](Anvil_설계서_v3_초안.md)과 [작업계획서](../WORK_PLAN.md)다. 아래는 통합 전 판단/내용을 보존한 이력이며 별도 추가 권위 문서가 아니다. 과거 r5/승인 상태 표현은 당시 시점으로 읽는다.

## 1. 지위와 변경 범위

2026-10-15, Main 어울, 보완 r1. 신산님의 ‘제3자 의견을 검토하고 맞는 부분을 보완한 뒤 계속 진행’ 지시에 따라 작성했다. 설계 r5의 사용자 소유 원본·교체 가능한 도구·기능 전체 범위·단독 제어·안전 경계를 유지하며 누락된 실행 순서/책임/검수 기준을 상세화한다. 기준 r5와 승인 P01 HTML/공식 양식 원본은 보존한다.

이 보완은 제품 구현 완료, 새로운 사용자 승인, 실제 Agent/DB/권한/배포 실행 승인이 아니다. 기존 r5의 ‘검토 전’은 작성 당시 상태이고 현재 승인 범위는 P01 REVIEW-01/02, TECH_DECISIONS TD-01, WORK_STATUS의 직접 응답 기록을 따른다. 전체 설계나 미작성 계약을 소급 승인으로 만들지 않는다. 계획 r3의 사용자 승인을 ‘잠정’으로 낮추거나 P01~03으로 임의 축소하지도 않는다. 후속 구현은 각 실제 선행 계약/환경과 실행 승인 경계를 충족해야 한다.

## 2. 실행보다 먼저 완성할 안전 기반

- FN01: Anvil 사용자 인증·로그인/로그아웃·만료, 프로젝트 소유/참여 조회 권한, 클라이언트 식별과 최초 단독 제어 세대의 서버 저장을 소유한다. 구체 인증 방식/초기 등록은 P02 결정 계약을 따른다. Agent 계정과 분리하고 실제 계정/권한 변경은 별도 실행 경계를 지킨다.
- FN11: 모든 변경 명령의 현재 사용자/클라이언트·제어 세대·범위/버전·일회 승인·중복 방지와 허용/거절 감사 기록을 집행한다. FN08의 필수 선행이다.
- FN08: 실행 ID/세대·허가 실경로·겹치는 쓰기 범위·실제 프로세스 소유 관측과 durable 전달/spool을 소유한다. 문자열 경로 일치나 DB 잠금만으로 외부 쓰기 회수를 보장했다고 하지 않는다.
- FN15: 앞에서 저장/집행한 제어권을 사용하는 사람/기기 인수의 요청→안전 요약→수락·원자적 권한 전환을 완성한다. FN15 전에는 최초 제어 클라이언트만 변경할 수 있고 다른 클라이언트는 조회만 가능하다. ‘제어권 기반이 없음’을 임시 전체 허용으로 우회하지 않는다.

따라서 FN15의 전체 UI/인계가 나중에 와도 FN11/08의 안전 확인을 미루지 않는다. 업무 ID/44개 전체 범위는 유지한다.

## 3. 외부 도구 타당성 판단

P02에서는 공식/설치 지원과 통제 방식·미확인을 문서화한다. 실제 유료 호출이나 쓰기 시험을 P02 문서 업무에 끼워 넣지 않는다. P03 환경과 FN01/FN11 안전 기반 뒤 FN06의 제한된 실제 검증을 가능한 이른 시점에 수행하고, 이 결과가 있어야 실제 변경 역할/FN08 실행을 허용한다. Stage B 전체가 끝나야만 FN06을 시작한다는 장벽은 없다.

도구별 필수 확인은 지시/세션 식별, 상태/원문 수집, 결과/파일·시험 증거, 도구 자체 승인 응답, 중지와 실제 회수, 허가 경로/쓰기 통제다. 임무가 승인 응답/쓰기 등을 필요로 하지 않으면 해당 없음의 근거를 기록하되 기능 자체 미지원과 혼동하지 않는다.

- `확인`: 정확 제품/버전·환경·실행 ID·정상/중요 실패·잔류/회수 증거가 있음.
- `미확인`: 공식 문서/도움말만 있거나 해당 실제 증거가 없음. 변경 임무 준비 완료가 아님.
- `미지원`: 공식/실측으로 부족한 기능과 적용 버전을 확인함.
- 임무별 필수 통제 충족 시에만 배정 가능. 부족하면 해당 실행 경로를 차단하고 공식 대안/다른 도구·영향을 제시한다. 모든 후보가 필수 통제를 충족하지 못하면 사용자 결정 없이 ‘관측만 하는 제품’으로 축소하지 않는다.
- 첫 실제 도구 검증은 Stage C 실행 경로의 진입 조건이다. 두 번째 실제 도구와 총괄 교체 검증은 Stage D/IX04에 여전히 필수다. 단일 도구 성공을 제품 목표 달성으로 치환하지 않는다.

## 4. 중지와 안전 회수

기존 설계는 강제 종료를 영구 금지한 것이 아니라 자동 복구 대안으로 쓰지 않는다는 뜻이다. 지원 중지 요청→실제 도구/소유 프로세스·쓰기 상태 관측→정리 확인 순서를 유지한다. 미확인은 안전 차단이며 성공 아님이다.

중지가 불가능하면 정확한 소유 실행/프로세스·자료 손실 가능성·기록 공백·대안을 제시하고 사용자 결정을 받는다. 특정 실행의 강제 종료가 별도로 지시된 경우에만 그 대상/영향/정리 증거를 확인하며 공유 프로세스·서버/WSL 재시작·ACL 변경으로 확대하지 않는다. timeout 경과만으로 자동 kill/새 writer 시작을 허용하지 않는다. 상세 OS binding과 이탈/잔류 시험은 P02/FN08/FN13에 남긴다.

## 5. 이해 대조와 완료 증거

이해 검토는 자유로운 인상 평가가 아니라 다음 항목별 `기준 원문/버전 → 대상 응답 → 일치/불일치/부족 → 확인 주체/근거`를 보관한다.

1. 프로젝트 목적과 이번 임무의 이유.
2. 헌법·최신 지시·허용/금지 범위.
3. 유지할 결정과 결정 이유.
4. 완료된 것·미완료·정확한 현재 위치.
5. 실제 소스/환경 상태·인계 이후 차이·누락/회수 공백.
6. 다음 행동과 완료/중지 조건, 모르는 부분.

ID/hash/권한/누락/현재 위치는 구조화 검사로 대조한다. 목적/이유 등 의미 판정은 총괄이 근거를 제시하되 Agent 스스로 합격 선언하지 못한다. 필수 항목 불일치·부족은 보완하며 원문과 실제 상태의 모순을 모델 점수로 덮지 않는다. 총괄 교체의 최종 확인은 사용자, 단계 교체는 총괄이라는 기존 책임을 유지한다. 필수 기준은 맥락 예산 때문에 버리지 않으며 무조건 1-hop만 전달하지 않는다.

완료 증거는 수행자 주장·실행기 직접 관측·시험 산출물·검수자 확인을 구별한다. 가능한 경우 실행기가 허가된 시험 명령의 실행/종료/산출물을 직접 관측하고 정확 commit·명령·환경·hash와 연결한다. 검수자는 실제 파일/결과를 독립 확인한다. 변경·위험·증거 부족 때문에 필요한 시험만 재현하며, 불변인 모든 시험을 무조건 다시 돌리는 규칙은 추가하지 않는다. 직접 실행/재현이 없으면 그 범위를 미검증으로 남긴다.

## 6. 서버 확정 문서와 소스 파일

문서의 Anvil 확정 버전과 저장소 파일은 같은 객체라고 가정하지 않는다. 연결 시 `documentId/version/hash ↔ sourceRootId/relativePath/blobHash/commit`의 투영 관계를 명시한다. 내보내기/가져오기, 임무 착수·결과 제출·재개 전에 필요한 연결 문서의 실제 hash를 대조한다.

외부 편집으로 다르면 `드리프트`이며 자동 덮어쓰기/확정/실행 기준 변경을 하지 않는다. 화면에서 서버 확정본 유지·저장소 수정안을 변경 제안으로 수집·별도 문서로 분리 중 정확 영향을 보여준다. 실제 파일 복원/쓰기에는 해당 권한/승인을 적용한다. 영향을 받는 임무만 준비를 다시 확인하고 무관한 작업은 계속한다. 연결하지 않은 소스 파일까지 주기적으로 전수 수집하지 않는다.

## 7. 자료 보호와 환경 경로

자료 최소 수집·비밀 제외/마스킹·프로젝트 접근 통제는 함께 적용한다. 마스킹이 완벽하다고 하지 않는다. 노출 의심 자료는 공유/전송·일반 조회를 제한하고 관련 자료 ID·범위·수신 지점을 비밀 원문 없이 기록한다. 사용자에게 노출 범위와 필요한 인증정보 회수/교체·보존/삭제 선택을 알린다. 원문/감사 자료를 자동 파괴하거나 외부 계정을 임의 변경하지 않는다. spool/서버/백업 암호화·키 관리·보존 수치는 THREAT_MODEL/P02 결정 계약으로 구체화한다.

소스의 표시용 상대 경로와 실행 호스트의 실제 경로·파일 정체성을 분리한다. Windows/WSL 경로는 환경에 등록된 매핑만 사용하며 단순 문자열 치환하지 않는다. 상위 경로 이탈·링크·특수 경로·볼륨/대소문자/권한 차이를 검증하고 요청 직전 경계와 실행 시 경계를 확인한다. CRLF/LF/Git 속성 차이는 시작 진단에 표시하되 사용자 파일을 일괄 변환하지 않는다. 성능/파일 관측 문제는 실제 환경 시험 전 원인으로 단정하지 않는다.

## 8. 상태 표기와 검토 시점

진행·기능 사용 가능성·시험·수행자 제출·검수는 서로 다른 축이다. 기능 사용 가능성의 공식 표시값은 `구현 완료·핵심 동작 확인 / 구현했지만 동작 미확인 / 부분 구현 / 미구현`이다. r5의 축약 표시는 이 값의 별칭으로만 읽고 추가 상태를 만들지 않는다. 명령/실행 상태는 INTERFACES에 별도 정의한다.

Stage A는 계약/환경/실행 경계, C는 첫 실제 Agent 핵심 흐름, E는 사람/기기·복구/설치형 결과를 사용자에게 짧게 공유한다. 일반 작업마다 대기하거나 과거 DIR 강제 중단점을 이월하지 않는다. 사용자의 검토·결정이 필요한 항목만 기다리고 독립 작업은 계속한다. 모바일 승인 전용 위임·범위 축소·새 자동 강제 종료는 이번 보완에 포함하지 않는다.
