# F-08 WorkInstruction — GEMINI adapter

- 승인 범위: 작업계획서 F-08의 GEMINI adapter와 결정론적 계약 테스트. `generate`, `stream`, host transport `health`, model `discovery`, request ID, abort, final usage, quota/error/retry-after mapping을 구현한다.
- 제품 exact5: `packages/providers/gemini_adapter.py`, `packages/providers/gemini_models.py`, `packages/providers/gemini_errors.py`, `tests/providers/test_gemini_adapter_f08.py`, `docs/04_test_reports/F-08_COMPLETION_REPORT.md`.
- 기준: 설계서 canonical Provider ID `gemini`; 통합검증 `AV-OPS-010`, `AV-OPS-011`, `AV-FLOW-019(GEMINI)`; F-02 model snapshot·routing·Secret 경계 및 기존 Provider 코드를 수정하지 않는다.
- OmniRoute `release/v3.8.51` commit `20f39008892b683a639063fb8aed8c07782fb0c3`의 `open-sse/config/providers/registry/gemini/index.ts`와 `shared.ts`가 Provider 기준이다. `format=gemini`, `executor=default`, base `https://generativelanguage.googleapis.com/v1beta/models`, host 전용 `x-goog-api-key`, model-scoped `:generateContent`/`:streamGenerateContent?alt=sse` 경로 및 정적 등록 모델 8개를 보존한다. TTS 전용 `gemini-3.1-flash-tts-preview`는 정적 discovery에는 출처와 함께 표시하되 text `generate`/`stream`에는 capability 불일치로 송신 전 거부한다. 등록 목록의 실제 가용성은 주장하지 않는다.
- Google 공식 API는 Gemini wire·오류 해석의 보조 기준이다. 요청은 `contents`의 user text parts를 쓰고 모델은 검증된 경로에만 둔다. 성공 응답의 `candidates`, `finishReason`, `responseId`/`modelVersion` 및 `usageMetadata`를 검증한다. `STOP`과 text part가 없는 safety/blocked/unsupported 결과를 성공으로 승격하지 않는다. `totalTokenCount`가 `promptTokenCount + candidatesTokenCount`보다 클 수 있으므로 생각 토큰을 임의로 버리거나 0으로 만들지 않고, Gateway `TokenUsage`는 검증된 total에서 prompt를 빼는 방식으로 보존하며 원본 구성 수치는 receipt에 기록한다. 미완성·불일치한 최종 사용량은 fail-closed한다.
- 기존 F-03~F-07과 같은 주입형 host transport/GatewayRequest/Response 경계를 따른다. host가 endpoint와 key 주입·실제 네트워크를 소유한다. request ID는 송신 전 입력 fingerprint에 결박하고 동일 입력 성공 replay는 결정적이며 실패 뒤 동일 입력 재시도만 허용한다. 다른 입력·operation 재사용은 송신 전 거부한다. Stream final frame의 usage와 response ID 일관성, pre/post-send abort 및 `PROVIDER_FINAL` 출처를 검증한다.
- `discovery`는 OmniRoute static registry의 출처·비실시간 성격을 표시하고 credential health로 승격하지 않는다. `health`는 host가 실제 authenticated model probe 근거를 제공한 경우에만 `AVAILABLE`로 판정한다. 이 Package는 구체적인 HTTP transport wiring 또는 live probe를 실행하지 않는다.
- 오류는 Gemini의 `error.status` 및 `details[].reason`과 HTTP status를 함께 해석한다. 400의 명시적 API key invalid와 일반 invalid request, 401 auth, 402 credit depleted, 403 permission, 404 model/path, 429의 rate/spend ambiguous를 근거 없이 혼동하지 않는다. 명시적 rate 근거가 있을 때만 retryable rate로, `Retry-After`만 있을 때는 원인 단정 없이 처리한다. 408/5xx 일시 오류, retry-after 형식·상한, unknown 실패의 fail-closed, 오류·header·receipt의 credential 원문 차단을 테스트한다.
- 테스트는 결정론적 fake host transport로 수행한다. 실제 Gemini key·API·network·DB·browser·WSL·deployment는 이 host-only Package에서 실행하지 않는다. 키 부재·무효는 실제 연동 미검증으로 기록하며 제품 결함 PASS/FAIL로 허위 집계하지 않는다.
