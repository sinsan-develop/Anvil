# F-18 R43B2 WorkInstruction — WSL-server 격리 정식 실행 검증

- Main 어울의 검증 전용 작업이다. 기준 `codex/f18-wsl-ops` R43B1 종료 seq1653·worker/write lease=null. 새 epoch29 Main worker lease·G-05 PASS 후에만 격리 자원 생성. 제품 write lease와 제품 mutation은 없다. B1 exact SHA는 `160e98ee0ee2a71ec047215c58ad40c21eeedc36`이며 WSL checkout은 게시된 B2 control SHA를 Git으로 받아 B1 SHA를 조상으로 확인한다.
- 대상은 `ssh WSL-server` 하나이며 로컬 Windows는 개발·격리 Chrome/SSH 터널만 사용한다. 로컬 WSL, `ysna-server`, Production, 공개 도메인·운영 credential·기존 Chrome 프로필·OS 전역 CA 변경은 금지한다. `/srv/anvil-wsl`은 root 소유이므로 전용 checkout은 `daon` 소유 `/home/daon/anvil-f18-r43b2-qa`, 합성 material은 `/home/daon/anvil-f18-r43b2-material`로 고정한다. 둘 다 생성 전 부재 확인, Git 파일과 합성 자료 분리, 검사 종료 즉시 정확한 자원만 제거한다.
- Compose project `anvil-f18-r43b2`, 전용 services `web/api/worker/postgres/minio/oidc-issuer`, network `anvil-f18-r43b2_internal`·`anvil-f18-r43b2_ingress`, Web host bind `127.0.0.1:8444`만 허용한다. image는 Git archive exact SHA에서 Dockerfile.f18의 web/api/worker와 QA issuer를 빌드한 전용 태그·ID만 사용하고 release SHA label을 확인한다. PG18/MinIO는 검증된 digest/image ID를 사용한다. 공유 `anvil-web`·`local-postgres` 및 다른 project 컨테이너/network/volume/image는 정지·재시작·정리하지 않는다.
- 합성 CA/cert SAN `anvil-f18-qa.local`, issuer RSA key·client Secret·trust JSON·Compose env는 material 디렉터리에만 생성하고 mode/UID101·10001 읽기, read-only mount, JWKS 공개키 일치, Git/로그 비노출을 검사한다. OS 전역 trust store는 건드리지 않는다. PG18 전용 DB `anvil_f18_qa`, 비관리자 `anvil_app` role 및 migration head `0019_oidc_sessions`를 같은 Compose project 안에서 bootstrap하고 실제 SQL 확인한다. 필요하면 재기동은 이 전용 project 안에서만 수행한다.
- 실제 `docker compose config`, image ID, `nginx -t`, HTTPS TLS/issuer auth→code→token→callback→session 및 재사용·잘못된 Secret/PKCE/nonce/issuer 등 거부를 검증한다. Windows Chrome은 신산님이 승인한 임시 격리 프로필·headless/CDP, 로컬 SSH `-L 8444:127.0.0.1:8444`, profile 한정 DNS 매핑으로만 사용한다. browser Network의 same-origin 및 내부/localhost 직접 호출 부재를 확인한다. Web UI에 로그인 동선이 없으므로 API 인증 흐름과 UI 사용자 인수를 구분한다.
- 자원 생성 전 inventory·owner·이름·수명·정리 절차를 `WORK_STATUS`에 기록한다. 종료 시 전용 Compose `down`으로 container/network를 제거하고 image ID가 전용임을 확인한 뒤 전용 image·checkout·material·터널·Chrome 프로필/프로세스만 제거한다. `test ! -e`/Docker label/port/프로세스로 residue0과 공유 서비스 불변을 확인한다. 실패도 실제 결과·미검증·오류 횟수와 정확한 다음 조치를 기록하며 PASS로 승격하지 않는다. 중요한 위험/범위 변경이 필요하면 제품 mutation을 중단한다.
