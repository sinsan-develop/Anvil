### 1.1 업무를 나누는 기준

작업은 파일 수·소요 시간·프롬프트 길이로 자르지 않는다. **한 담당자가 명확한 결과를 책임지고, 검수자가 인접 업무와 구분해 합격/보완 판정할 수 있는 업무**로 나눈다. 내부 RED→구현→GREEN→기록은 같은 업무에 포함한다. 단순 폴더 생성·버튼 하나·테스트 한 개를 독립 성과로 세지 않는다.

- UI: 화면·사용자 조작·상태·이동·접근성 책임. 화면만 연결했다고 기능 완료로 표시하지 않는다.
- FN: 처리 규칙·저장·조회·권한·상태 전이·연동 책임. API만 있어도 사용자 기능 완료는 아니다.
- IX: UI와 FN을 실제 이어서 핵심 사용자 흐름을 확인하는 통합 업무. UI/FN 각 담당의 기본 검증을 뒤로 미루는 곳이 아니다.
- P: 결정·화면 검토·개발 준비. 제품 기능 구현 건수에 넣지 않는다.

계획은 아래 상세 문서와 하나의 계약이다. **공통 위임 계약 + 해당 업무 카드 + 실제 시작 패킷**을 한 묶음으로 전달해야 한다.

|---|---|

### 1.2 전 업무 공통 제약

1. 프로젝트·목적·헌법·지식은 사용자 소유. 총괄도 도구이며 교체 가능. 자체 코딩 엔진을 만들지 않는다.
2. 첫 화면은 프로젝트 목록, 주 화면은 절차/대화·작업/자료의 3영역. Dashboard는 보조다.
3. 같은 파일·기능의 writer는 한 명. 현재 writer가 쓰는 경로를 Main이나 다른 Agent가 수정하지 않는다.
4. 과거 자료·사용자 dirty/untracked·원문·기존 정상 기능을 보존한다. 완료 작업은 변경 영향 없이 반복하지 않는다.
5. 서버 권한·중복 명령·동시 writer·비밀 보호·데이터 손상 위험은 1단계에서 검증한다. Agent 자체 안전 절차를 우회하지 않는다.
6. mock/계약/단위 시험과 실제 Agent·DB·브라우저 확인을 분리한다. 미실행은 PASS가 아니다.
7. 기능 범위·권한·데이터·운영·외부 비용의 새 경계는 승인 절차를 따른다. 작업계획 작성 요청만으로 실행하지 않는다.
8. 서비스 교체·서버 설치·실제 migration/지속 데이터·Secret·인증서·원격 공개·Oracle 반영은 이번 문서 작성에 포함하지 않는다.
9. 설계 기술 미확정을 담당자가 임의 선택하지 않는다. P02의 파일/API/명령 명세를 기준으로 구현하며 계약 변경은 영향 기록 후 처리한다.
10. 원격 저장소는 사용자가 비워 둔 상태다. 새 계획·설계 업로드를 포함한 Git 외부 쓰기는 실제 지시/승인 대조 전 자동 수행하지 않는다.
11. 이번에 적용하는 설계·계획·위임·검수·변경·오류·인계 방법은 Anvil이 표준화·시스템화할 원형이다. 원문과 합의·제안·시행착오를 구분하고 공통 기준/프로젝트 적용 버전/실제 실행·검수로 연결한다. 문서만 작성했다고 시스템화 완료로 세지 않는다.
12. 현재 운영 진입점은 root AGENTS.md의 v3 절이다. 과거 v2 Phase/DIR/lease 규칙은 새 Stage의 Gate로 이월하지 않는다. 기준 hash/승인 범위와 관측 시점은 [기준선 manifest](contracts/BASELINE_MANIFEST.json)로 구분하며 문서 미커밋을 commit 완료로 표시하지 않는다.

## 2. 단계 지도·실행 순서

‘Stage’는 통합·검수 경계, ‘업무 ID’는 Agent에 위임하는 단위다. 단계 전체를 한 Agent가 맡아도 개별 업무 검수 기록은 유지한다. 아래 순서는 기본이며 확정된 선행 조건을 만족하면 무관한 업무는 진행할 수 있다. 코드 writer 병렬 실행은 자동 약속하지 않는다.

안전 기반은 FN01(인증·초기 단독 제어)→FN11(변경 명령/승인·감사)→FN06(조기 제한 실제 능력 검증)→FN08(실행/회수)의 순서로 먼저 연결한다. FN06의 선행이 충족되면 Stage B 전체 종료를 기다리지 않고 시작 가능하다. 실제 호출·변경 시험은 별도 허용 범위를 대조한다. 다른 코어 문서/화면 개발을 외부 지원 미확인 때문에 전부 막지는 않으며 단일 writer 원칙은 유지한다. FN15의 사람/기기 인계는 앞서 구현한 제어 기반을 소비한다.

| Stage | 사용자에게 생기는 결과 | 구성 업무 | 종료 검수 |
|---|---|---|---|
| A 설계·실행 준비 | 검토한 상세 동작과 구현 가능한 계약 | P01,P02,P03 | 클릭형 검토·기술/파일/API·검증 명령·환경 경계 확정 |
| B 방법론·프로젝트·지식 원본 | 프로젝트를 만들고 절차·문서·헌법을 저장/재조회 | UI00~UI03,UI06,UI10; FN01~FN05,FN11; IX01 | 프로젝트 생성→방법론→문서→추적→지식 실제 저장 |
| C 기존 Agent 실제 작업 | 화면에서 임무를 전달하고 실제 결과 확인 | UI04,UI05,UI08,UI11; FN06,FN08~FN10,FN12,FN13; IX02,IX03 | 실제 기존 Agent 한 종류 작업·승인·모드·결과 판정 |
| D 최소 손실 교체·변경 통제 | 기존 도구 무응답에도 새 도구에서 미완료 지점 재개 | UI07,UI09; FN07,FN14; IX04 | 같은 도구 새 세션·다른 도구·총괄 교체 실제 확인 |
| E 사람·기기·원본 복구 | PC/모바일 단독 제어, 안전 복원·설치형 산출물 | UI12~UI14; FN15~FN18; IX05,IX06 | 중복 승인/동시 제어 방지·복구·데스크톱 핵심 확인 |
| F 1단계 개발 완료 후보 | 전체 기능을 실제로 사용·검토할 수 있음 | IX07 | 화면/기능별 4상태, 미확인·미구현 공개, 핵심 동작 증거 |

UI01~14의 뷰 착수는 UI00과 해당 P01 승인/P02 계약·P03 준비를 대조한다. 이때 fixture로 작성한 화면은 **부분 구현**이며 실제 지시/저장 성공을 표시하지 않는다. 기존의 UI/FN 완료 선행 목록은 완료·연결검수 열에 그대로 유지했다. 다른 P/FN/IX는 원래 선행을 두 열에 동일하게 기록한다. 기계 파서는 쉼표 문자열/주석을 권한으로 추측하지 않고 이 두 필드의 의미를 구별해야 한다. 가짜 데이터의 제품 승격·보안 우회는 금지한다.

P02의 확정 계약으로 UI 단독 뷰를 착수하는 조건과 위 표의 통합 완료 선행을 구별한다. 이는 병렬 writer 허용이 아니다. 전체 44업무는 1단계 범위를 줄이지 않고 유지하며, 코어 저장/첫 도구/교체/사람·복구의 사용 가능한 결과를 순서대로 보여준다. 상대 규모·일정은 P02/P03의 실제 기술/외부 지원/작업 속도 확인 후 갱신하고 임의 납기를 약속하지 않는다. 우선 위험·재검토 지점은 [위험 등록부](contracts/THREAT_MODEL.md), 전체 설계/업무/시험 관계는 [추적표](contracts/TRACEABILITY.md)를 따른다.

### 2.3 위험 등록부와 재검토 책임

## 3. 위임 가능한 공통 시작 계약

### 3.1 실행 시작 패킷

담당자에게 ‘UI04 작업해’ 한 줄만 보내지 않는다. [위임 양식](work_packages/ASSIGNMENT_REVIEW.md)의 실제 값이 채워진 시작 패킷을 붙인다. 그 안에는 다음이 반드시 있어야 한다.

- 이 계획과 **해당 업무 카드의 경로·ID·개정**, 설계 절/ID·해시.
- 왜 하는지, 사용자에게 생길 결과, 포함·제외, 선행 업무의 수용된 결과.
- 공식 프로젝트 경로, branch/HEAD, 파일별 dirty 소유와 보존 대상.
- 실제 허용 파일 목록, 입력/출력 API·모델·상태·오류 계약, 소비 업무.
- 실행 환경·자원·도구·검증 명령의 실제 값, 허용·승인·금지 범위.
- 수행자가 해야 하는 기본 검증, 검수자가 재확인할 증거, 완료/미실행 조건.
- 현재 위치·오류 횟수·재개 지점·금지할 반복, 상세 상태 기록 위치.

P02/P03에서 계약·환경이 결정되기 전에는 코드 경로·명령을 추측해 후속 구현 패킷을 발행하지 않는다. 이는 계획 누락을 작업자 재량으로 떠넘기지 않기 위한 필수 바인딩이다. **지금 바로 위임 가능한 것은 승인 범위 안의 준비 업무이며, 구현 업무는 실제 시작 승인이 있어야 한다.**

### 3.2 파일 책임 지도

아래 코드 경로는 프로젝트 저장소 root 기준이다. 이 문서의 Markdown 링크는 `docs/` 디렉터리 기준이므로 `contracts/...` 링크와 코드 경로 `docs/contracts/...`는 같은 대상을 가리킬 수 있다. 기계 패킷은 경로 종류와 sourceRootId/relativePath를 명시하고 링크 표시 문장을 그대로 파일 권한 경로로 사용하지 않는다(설계 §2.4).

### 4.3 판정과 실제 진행 기록

Agent 제출 상태: `COMPLETED / FAILURE_REPORT / INCOMPLETE / BLOCKED / CANCELLED`. 검수 결과: `ACCEPTED / REWORK / BLOCKED / NOT_EXECUTED`. `COMPLETED`와 `ACCEPTED`는 다르다. 기능 상태는 `구현 완료·핵심 동작 확인 / 구현했지만 동작 미확인 / 부분 구현 / 미구현`으로 별도 기록한다. 진행·명령/실행·검증 범위도 같은 상태열로 합치지 않는다.

등록부에는 시작 시각·담당·기준 commit을, 종료 시 결과·검수·증거·미검증을 추가한다. 단순 체크 완료로 덮어쓰지 않는다. `WORK_STATUS`는 시간순 상세 기록이며 계획의 현재 상태와 상호 링크한다. 세션 중단 시 업무 상태 파일에서 재개할 수 있어야 한다.

### 4.4 QA·rollback·승인

모든 변경 명령은 FN01/FN11의 실제 인증·단독 제어/세대·중복/범위 확인을 먼저 통과한다. 각 작업의 허용/거절·기준 버전·명령/실행·증거 연결 감사는 FN11 공통 계약, 실행 원문/관측은 FN08, 결과 판정은 FN12가 소유한다. 후속 기능을 기다리며 임시 전체 허용을 두지 않는다.

모든 카드는 공통 QA 규칙을 상속한다. 자원 생성 전 이름·소유 업무·대상 환경·목적·수명·정리를 기록하고 승인 범위와 대조한다. QA 엔터티 ID를 증거에 연결한다. 실패/중단 때도 일회성 자원만 정확히 정리하고 잔류를 확인한다. 실제 서비스·사용자 데이터·기존 인증 자료는 임시 자원으로 취급하지 않는다.

코드 rollback은 해당 업무 변경만 안전한 기준과 비교해 복구하는 계획을 제시한다. 저장 기능은 migration 전후·데이터 손실 여부와 백업/forward 복구를 명시한다. `down` 명령이나 reset을 무조건 실행하지 않는다. 복구가 파괴적이면 별도 승인 후다. 외부 Agent가 만든 변경도 실제 diff를 검토해 범위를 특정한다.

## 5. 통합·설치·배포 경계

이 문서는 개발과 검증 계획이다. FN18은 설치형 **제품 코드·패키지 산출물의 개발**이며 사용자의 실제 PC 설치/제거/환경 교체 작업 지시가 아니다. IX07의 WSL 핵심 기능 검증은 승인된 환경에서 수행하며 실제 서비스 구성·교체가 필요하면 별도 설치·배포 계획으로 분리한다.

IX08은 Oracle에서 수행할 검증 범위를 정의한다. 실제 이전·서비스 반영·rollback 실행은 별도 승인된 설치·배포 계획과 exact commit/image를 선행조건으로 한다. 미구현 기능을 Oracle 정밀 시험 항목으로 숨기지 않는다.

## 6. 계획 변경과 미결정 관리

- 설계 hash 변경 시 영향 업무를 표시하고 무관 업무는 유지한다. 의미 변경은 설계 승인→계획 개정→해당 패킷 재발급 순서.
- 업무 ID는 재사용하지 않는다. 분할/통합 시 구ID→새ID·사유·잔여·증거를 보존한다.
- Agent 변경은 업무 완료 취소나 최초 재시작이 아니다. 상세 상태·미커밋·오류·다음 행동을 인계한다.
- P02에서 지원 불가인 도구는 ‘미지원’, 검증 못 한 도구는 ‘미확인’이다. 두 번째 도구 미확인 상태에서 교체 가능한 제품이 완성됐다고 하지 않는다.
- 성능/손실 한도·백업 정책 수치는 P02가 대표 측정안/근거를 만들고 사용자 확인을 받는다. 임의 합격값으로 바꾸지 않는다.
- 현재 원격 파일 정리 상태·기존 로컬 이력은 P03에서 읽기 대조하며 새 개발 기준 정하는 행위와 원격 재업로드를 구분한다.
- N1 문서 보존은 P03 기준선 준비에서 현재 branch의 정확 문서·연결 자산·manifest·현황을 선별하는 commit 범위로 관리한다. 기존 삭제/무관 변경을 일괄 stage하거나 새 branch/원격 업로드로 우회하지 않는다. 이번 보완에서는 commit·원격 쓰기를 실행하지 않는다.
