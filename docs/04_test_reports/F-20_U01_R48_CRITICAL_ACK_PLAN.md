# F-20/U-01 R48 Critical Alert 확인 절편 계획

- 기준: Anvil 설계 §29.2 Critical Alerts 확인 버튼과 작업계획 U-01. PMO `codex://threads/01a054f5-c2b4-7af0-b31a-c8148ef74642`의 2026-10-05 한정 승인. 기존 `codex/f18-wsl-ops`에서만 수행하고 F-20/U-01 전체 `ACCEPTED`로 승격하지 않는다.
- 의미: 인증된 운영자가 정확한 scoped `open`·`critical` 경고를 읽고 확인하는 ACK다. 사람의 설계·배포 승인이나 해결(resolution)이 아니다. 기존 audit `approval_id` 필드의 `ack:<opaque>` 값은 서버 발급 ACK 상관 receipt이며 `ApprovalRecord`나 다른 Gate의 인간 승인으로 사용하지 않는다.
- 계약: `POST /api/operations/alerts/{alertId}:acknowledge`와 `operations:alerts:acknowledge`만 추가한다. `dashboard:read`만 가진 actor, 다른 role/project/environment는 403. 알 수 없는 alert는 404, 이미 ACK/상태 변경/버전·evidence mismatch/경합은 409. 같은 actor·Idempotency-Key를 포함한 모든 replay도 409이며 durable replay 성공은 약속하지 않는다. 서버는 인증 principal의 actor, 현재 scoped alert의 evidence hash, 서버 생성 receipt만 감사 Event에 쓴다. 브라우저가 제시한 actor·approval ID·evidence hash는 신뢰하지 않는다. 기존 GET·POST callback body/schema·DB schema는 바꾸지 않는다.
- 요청 보호: 기존 공통 `_authorize`, Origin/CSRF, Idempotency-Key, If-Match, X-Target-Hash, X-Permission-Scope, Reason을 우회하지 않는다. 서버/포트에서 원본 alert의 scope·open·critical·version·evidence를 재확인하고 append-only ACK를 정확 한 번 기록한다. 둘 이상의 service 인스턴스 경쟁은 PostgreSQL 감사 sequence CAS에서 1승·1충돌로 끝내며 자동 재append하지 않는다. timeout 시 GET을 재조회하고, UI 성공은 2xx 및 동일 audit sequence 확인 후만 표시한다.
- 인증 복귀: 동일 origin 콘솔 root `/`를 OIDC redirect URI로 사용한다. 사용자 클릭으로 연 popup과 opener의 살아 있는 메모리에 독립 `browser_state` 및 popup Window를 유지한다. 합성 IdP가 popup을 `/`로 돌려보내면 첫 실행에 code/state query를 `history.replaceState`로 제거하고 정확 origin으로 opener에게 전달한다. opener는 popup Window·origin·state를 대조한 다음 기존 `POST /auth/oidc/callback`을 호출해 서버 pending state·PKCE 검증을 통과한 CSRF를 메모리에만 보관한다. 반환된 state를 검증 없이 browser_state로 복사하지 않는다. popup 차단/소실, 직접 callback GET, 중복·state 불일치, 새로고침/토큰 소실은 fail-closed 재인증이다. 토큰은 sessionStorage/localStorage/DOM/log/URL에 넣지 않는다.
- 검증 경계: 로컬 TDD 및 기존 API/GET/auth/Web 회귀, typecheck/lint/build 후 사설 `development`에 정확 SHA를 push한다. WSL-server에서만 pull한 동일 SHA의 격리 PG15, OIDC HTTPS·합성 IdP exact QA redirect allowlist, 실제 Chromium 클릭/Network로 양성·음성·권한·CSRF/Origin·경합을 검증한다. 합성 IdP/DB/cert/browser/temp는 종료 시 정확 대상만 정리하고 잔여0 확인한다. 공유/외부 IdP, `ysna-server`, Oracle/Production 및 실제 IdP 호환은 미실행·미검증이다. 첫 redirect GET URL/Network의 code/state 일시 노출은 query response mode의 잔여 위험이며, WSL 전용 access log off, `Referrer-Policy: no-referrer`, no-store, 첫 실행 URL 제거 후 history/DOM/후속 Referer 잔여0을 확인한다. 공유 proxy/access log는 검증 범위 밖이다.
- rollback: 해당 제품 diff를 정상 revert하여 기존 redirect URI·GET 동작을 복원하고 합성 QA allowlist를 원복한다. 이미 기록된 ACK Event는 삭제·재작성하지 않으며 잘못된 ACK 정정은 별도 설계·승인 전에는 수행하지 않는다.
- 제외: DB migration, ApprovalRecord lifecycle, 기본 role 일괄 권한 부여, Queue HEALTHY 추정·liveness 계약, 필터/나머지 운영 카드, 새 branch/main 병합, 공유·외부 IdP 설정, 운영 배포.
