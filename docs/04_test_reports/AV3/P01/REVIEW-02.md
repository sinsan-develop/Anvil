## 검증 증거와 한계

- `node docs/design/prototypes/core-workflow/verify.cjs` exit0: JS 구문, 14경로×8상태 렌더, 입력 보존/교체, 그래프 검사/배치, 4단계 생성/실행 분리, 공식 양식 검사/조회, 파일 형식/시안 크기 제한, 줄별 추가/삭제, 정지/대상 기능/권한·계획 개정의 재개 차단. 필수 검사를 느슨하게 바꾸지 않았다.
- 브라우저 핵심 확인: 문서 선택→탭 읽기→87행 비교·원문 미변경; 만료 후 미전송 입력 유지/전송 비활성; 대상 기능 부족 시 재개 불가→조건 충족 후 활성; 변경 승인 뒤 계획 개정 전 재개 불가; 지식 정정에도 원문·이전 내용 보존; 모바일 동일 AP-01 일회 결정; 인수 뒤 이전 클라이언트 읽기 전용. v11의 기존 소스 상태와 v12의 빈 목록→4단계 생성→준비 필요 프로젝트 표시도 확인했다.
- 브라우저 오류 로그 조회는 빈 목록이었다. 실제 provider/API/DB/권한·코딩 Agent·설치형·운영환경 시험이 아니며, 112조합을 모두 실제 브라우저로 실행했다고 주장하지 않는다. 이후 아래 직접 응답으로 시안·양식의 사용자 승인을 받았다.
- [.md/.txt] 파일은 선택한 파일만 로컬 탭에서 읽고 업로드하지 않는다. 1MiB는 시안의 안전 제한이며 제품 지원 크기/파서는 P02에서 결정한다. 줄별 비교는 복잡한 재배열의 최소 편집 거리 계산기가 아니다.
- 공간형 이동은 방향 버튼/키보드로 제공한다. 자유 드래그/자동 배치는 없다. 실제 설치 도구의 지원·연결과 사용 한도는 미확인으로 표시한다. S14의 실제 백업 위치/주기·설치/업데이트 상세는 P02/P03 및 후속 제품 업무에서 확정·구현한다.
- 형식 검사로 사실성·시험 실행·렌더 첨부·의미 품질을 자동 합격시킬 수 없다. 양식 목차만 채운 초안은 부족으로 표시하며 작성 결과 보관 상태는 ‘검토 대기’다.
